## 3. Discrepancies & Blockers

1. **Root cause: `03_tickets.md` was generated against the superseded `02_architecture.md`, not the current `02_technical_design.md`.** Every other finding in this report traces back to this one fact. The two design documents disagree on the error-handling strategy (thrown exceptions vs. `Result<T>`/`DomainError`), the aggregate base type (`AggregateRoot<string>` vs. `AggregateRoot<SubjectId>`), the background-worker transport (`IHostedService`/Redis vs. MassTransit consumer — a documented **hard blocker**, MIG-06), and the scope of the slice itself (`02_technical_design.md` includes the full `SiteComplianceCache` aggregate and its 3 endpoints; the ticket backlog has none of it).
2. **The entire site-compliance sub-domain is unticketed:** `SiteComplianceCache` aggregate, `ISiteComplianceRepository`, `SiteComplianceCacheConfiguration`, and all 3 `MapSiteComplianceEndpoints` routes (`/sites/{id}/activate`, `/webhooks/etmf`, `/sites/{id}/compliance-status`).
3. **FluentValidation validators have no ticket.** Every request DTO the design specifies a validator for (`SubjectCreateRequest`, `SubjectConsentRequest`, `SubjectStateUpdateRequest`, `EtmfCompletenessWebhookPayload`) is unvalidated in the backlog as written.
4. **Two explicitly-flagged blocking prerequisites are absent:** the `GxPAuditInterceptor`/`AggregateRootBase` generalization and Merkle-chained `AuditLogEntry` writes (§4.4) — without which 21 CFR Part 11 audit-field population silently fails for every aggregate in this slice.
5. **`MIG-SUBJ-007` specifies the architecture Rule 8/MIG-06 explicitly forbids** (an `IHostedService` background consumer instead of a MassTransit transactional-outbox consumer).
6. **No ticket ever references the `fixtures/` directory.** Golden-master parity — the mechanism `02_technical_design.md` §6 designs specifically to prove behavioral parity with the legacy Python system — has no assigned implementation ticket at all.
7. **The `SubjectResponse` under-population quirk (§2.6) has no ticket.** This is a named, deliberate, tracked (`TODO(CADENCE-EXEC-SUBJ-001)`) parity-preservation decision asserted by fixture `EDGE-010`; omitting it from any AC risks an implementer "fixing" it and silently breaking golden-master parity.
8. **Error taxonomy is essentially unticketed at the acceptance-criteria level** — 25 raise sites in the spec collapse to 4 generic status-code mentions in the backlog, with zero error-`Code` strings and zero `ProblemDetails`-envelope assertions.
9. **7 of 8 tickets omit the `TreatWarningsAsErrors`/`Nullable enable` hygiene line**, and no ticket carries an effort estimate for the Gate 6 size check to run against.

No dependency-cycle or layering violation was found (Gate 5 passes cleanly); no ticket is oversized by the layer-crossing check on its own terms. Every other blocker above is a coverage gap, not a graph-structure defect.
