# Continuous Integration

How CI is set up, which checks run where, and how to reproduce and fix each failure locally. The Cadence CLI runs as `pnpm cadence <command>` (a wrapper for `dotnet run --project packages/cli/src/Cadence.Cli.csproj --`).

## Workflows

| Workflow                  | Runs on                                                                                                                                         | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ci.yml`                  | Pull requests, merge queue (`merge_group`), pushes to `main`, `release/*`, and `v*` tags, and ref-guarded `workflow_dispatch` on protected refs | Style, lint and frontend builds, quality sentinels, Native AOT and docs builds, workflow and container security audits, .NET tests (including kernel consumer contracts), frontend unit and Playwright E2E accessibility, clinical workflow, and browser-to-DB TRX tests, GxP compliance checks, `CI Gate`, safe automerge, and CI-gated release/docs `workflow_call` callers                                                                            |
| `conflict-check.yml`      | Pull requests (opened, synchronize, reopened) and merge queue (`merge_group`)                                                                   | Emits `Check for Merge Conflicts` and fails via `git merge-tree --write-tree` when a PR conflicts with its base branch (`merge_group` runs validate the queued merge tree; shallow checkout, no `.NET` install)                                                                                                                                                                                                                                          |
| `production-pipeline.yml` | Called via `on: workflow_call` by `ci.yml` after all 11 CI gates pass on `main`, `release/*`, and `v*` tags                                     | Verifies NuGet/pnpm vulnerabilities and merged `.NET` + browser TRX/`*.database.txt` evidence (requiring `BrowserCorrectionReachesTheDatabaseWithItsReason`), stamps `tmp_etmf/` GxP RTM and IQ/OQ/PQ snapshots with `SHA256SUMS` and SLSA provenance (`retention-days: 400`), and on `v*` tags pushes digest-pinned GHCR images (`gateway`, `kernel-api`, `sce-python`, `sce-r`) and publishes an immutable GitHub Release with Native AOT CLI archives |
| `deploy-docs.yml`         | Called via `on: workflow_call` by `ci.yml` after all 11 CI gates pass on `main` (parallel to `release-and-archive`)                             | Builds `packages/ui`, the static VitePress portal (`pnpm docs:build` with unconditional `openapi`, `schema-doc`, `markdown`, and `rtm` checks), and the co-hosted staff and participant demos (`pnpm docs:stage-demos`), enforces the zero-exemption `check public-bundle` gate before `SHA256SUMS` and `upload-pages-artifact`, attests the packaged Pages archive (`artifact.tar`) with SLSA provenance, and deploys to GitHub Pages                   |

### `ci.yml` jobs

1. **Workflow Action Pinning & Actionlint Gate** (`actionlint`): runs `rhysd/actionlint` (`actionlint` on `PATH` in `cadence ci`) to enforce workflow YAML syntax, while the native `workflow-security` gate (run in `dotnet-quality`, pre-commit, and `pnpm cadence check`) enforces GitHub Actions supply-chain security across `.github/workflows/*.{yml,yaml}` and `.github/actions/**/action.{yml,yaml}` (40-character commit SHAs with inline version comments, `sha256:` digests on `docker://` references, `persist-credentials: false` on `actions/checkout`, least-privilege workflow permissions, typed `choice`/`boolean` `workflow_dispatch` inputs passed via `env:` rather than `${{ inputs.* }}` in `run:`, and ref-guarded `workflow_dispatch` triggers on workflows that deploy, attest, or publish).
2. **Lint and Static Verification** (`lint-and-static`): reuses the `cadence-cli-${{ github.run_id }}-${{ github.run_attempt }}` artifact from `native-aot-build`, installs the pnpm workspace and runs `pnpm build` (compiling `packages/ui`, `apps/web`, and `apps/subject-portal`), runs Prettier across all eligible repository files respecting `.prettierignore` and `check eslint` (`FrontendQualityGateService.CheckEslint`, linting all tracked JS, TS, Vue, MJS, and CJS files with `--max-warnings 0` via root `eslint.config.mjs`), Hadolint on Dockerfiles, ShellCheck on `*.sh` scripts, `bash tests/test_installer_checksums.sh` (verifying `.NET` installer SHA-256 checksum enforcement), `check markdown`, and `check api-clients` (`ApiClientValidatorService`, verifying generated web OpenAPI types and running workspace `tsc` and `vue-tsc` typechecking).
3. **.NET Quality & Sentinel Checks** (`dotnet-quality`): builds `Cadence.sln`, fetches `origin "$BASE_BRANCH"` on pull requests and `merge_group` runs, runs `cadence check --exclude prettier --exclude eslint --exclude actionlint --exclude hadolint --exclude detect-secrets --exclude api-clients --exclude vulnerabilities --exclude public-bundle --exclude architecture-tests --exclude unit-tests` with `--base "origin/$BASE_BRANCH"` on pull requests and `merge_group` runs and `--push-before "$BEFORE_SHA"` on pushes (executing the remaining 33 gates once, including `dotnet-format`, `dotnet-format-style`, `yaml`, `trailing-whitespace`, `end-of-file`, `clean-secrets`, `adrs`, `codeowners`, `workflow-security`, `rulesets`, `deid`, `security`, `schema-doc`, `openapi`, `demo-manifest`, `rtm`, `gxp-snapshot`, `baseline-ratchet`, `merge-readiness`, `branch-freshness`, and `duplication`), runs `Cadence.ArchitectureTests` (ArchUnitNET), and uploads `duplication_summary.json` (`duplication-summary-${{ github.run_id }}-${{ github.run_attempt }}`, `retention-days: 400`).
4. **Native AOT Compilation** (`native-aot-build`) and **Documentation Compilation** (`docs-build`): `native-aot-build` caches `./bin/cadence`, publishes `Cadence.Cli` as a Native AOT `linux-x64` binary into `./bin` on cache misses (failing on any trim or AOT warning), and uploads the run-scoped `cadence-cli-${{ github.run_id }}-${{ github.run_attempt }}` artifact (`retention-days: 400`, reused by `lint-and-static`, `docs-build`, `security`, `compliance`, and `v*` tag GitHub Release packaging); `docs-build` builds `packages/ui`, compiles the documentation portal (`pnpm docs:build` with unconditional `openapi`, `schema-doc`, `markdown`, and `rtm` checks and isolated child-process environments), stages both interactive demos into `/demo/` and `/subject-portal/` (`pnpm docs:stage-demos`), and verifies all three compiled public bundles (`docs/.vitepress/dist`, `apps/web/dist`, and `apps/subject-portal/dist`) with `node scripts/run-cli.js check public-bundle`.
5. **Security and Vulnerability Audit** (`security`): static security audit (`audit-security`), fail-closed NuGet (after `dotnet restore Cadence.sln`) and pnpm vulnerability audit (`check vulnerabilities`), non-mutating secret baseline verification (`check clean-secrets`), fail-closed `check detect-secrets` (`detect-secrets==1.5.0` in an isolated `venv`) and `check deid`, both scoped in `Cadence.Cli` (`GitRevisionScopeService`) via `--base "origin/$BASE_REF"` on pull requests and `--push-before "$BEFORE_SHA"` on pushes (falling back to every tracked file via `git ls-files -z` when `HEAD` equals the base ref or when `BEFORE_SHA` is all zeros, a tag, or a non-ancestor).
6. **Container Build & Vulnerability Scan** (`container-security`): builds `gateway`, `kernel-api`, `sce-python` and `sce-r` across a parallel matrix and runs fail-closed Trivy (`CRITICAL,HIGH`, `--ignore-unfixed`, exit code `1`) with distinct SARIF uploads (`trivy-<target>`) on pushes and on container or dependency pull requests. Locally, `cadence ci` runs `container-security` when changes against `--base` touch container or dependency inputs (or unconditionally on tracked-files fallback and `--job container-security`), checking `docker` daemon availability and `trivy` fail-closed while skipping only the GitHub Code Scanning SARIF upload.
7. **.NET 10 C# xUnit Verification** (`dotnet-tests`): `dotnet build` (warnings are errors), then `dotnet test Cadence.sln --configuration Release --no-build --results-directory TestResults/gxp --logger "trx;LogFilePrefix=gxp"` (including `packages/kernel/consumer-tests/Cadence.Kernel.ConsumerTests`) with `CADENCE_TEST_EVIDENCE_DIR=${{ github.workspace }}/TestResults/gxp` against a PostgreSQL 18 service container pinned to `PostgresTestImage.Image` (`CADENCE_TEST_POSTGRES`). Diagnostic TRX reports and `*.database.txt` fixture metadata are uploaded unconditionally in `trx-report-dotnet-${{ github.run_id }}-${{ github.run_attempt }}`. Locally either `CADENCE_TEST_POSTGRES` or `CADENCE_TEST_DOCKER=1` works for every database fixture ([TESTING.md](TESTING.md#tests-that-need-postgresql)), and `cadence ci` runs `bash scripts/test-check-database-test-results.sh` and `SyncGxPService.VerifyDatabaseEvidence` (`DatabaseTestEvidence.FindSkipped` with `repoRoot` plus `DatabaseTestEvidence.HasRecordedEnvironment`) so unit-only TRX reports, skipped integration/E2E tests, or missing `*.database.txt` files fail both `dotnet-tests` and `compliance` unless `--allow-db-skip` (or `--allow-skip`) is given. In GitHub Actions, `dotnet-tests` runs `scripts/test-check-database-test-results.sh` and `scripts/check-database-test-results.sh`, verifying that both `tests/Cadence.IntegrationTests` and `tests/Cadence.E2ETests` produced TRX reports and `*.database.txt` metadata in `TestResults/gxp` and failing on any `NotExecuted` database test except the opt-in lineage benchmark and browser correction check (`DatabaseTestEvidence.OptInTests`). Only after that gate passes does `dotnet-tests` upload `TestResults/gxp` as `gxp-test-evidence-${{ github.run_id }}-${{ github.run_attempt }}`; `test_outcome` waits on both the gate and evidence upload, blocking `compliance` and downstream release workflows on failure.
8. **Frontend Unit Tests** (`unit-tests`): Vitest across the pnpm workspace (`pnpm -r test`) plus the VitePress portal navigation suite (`pnpm exec vitest run --config vitest.config.mjs`, covering `docs/.vitepress/navigation.test.mjs`).
9. **Parallel E2E Accessibility Testing** (`accessibility-e2e`): runs on pull requests, pushes, and ref-guarded `workflow_dispatch` (`main`, `release/*`, and `v*` tags) and gates `ci-gate` (and transitively `automerge`), `release-and-archive`, and `deploy-docs`, executing Playwright E2E suites for `subject-portal` (`pnpm --filter subject-portal test:e2e`) and `web` accessibility and clinical workflows (`pnpm --filter web test:e2e` and `pnpm --filter web test:e2e:workflows` with `DEMO_MODE=false`, failing closed with exit code `1` if Playwright browser installation fails three times), plus `BrowserCorrectionReachesTheDatabaseWithItsReason` (`tests/Cadence.IntegrationTests`) against PostgreSQL 18 with `CADENCE_TEST_BROWSER=1`, writing TRX and `*.database.txt` evidence to `TestResults/gxp-browser` and uploading `gxp-browser-test-evidence-${{ github.run_id }}-${{ github.run_attempt }}` (`retention-days: 400`, ADR-2531).
10. **GxP Compliance & Qualification Reporting** (`compliance`): reuses `cadence-cli-${{ github.run_id }}-${{ github.run_attempt }}` from `native-aot-build` and downloads the verified `gxp-test-evidence-${{ github.run_id }}-${{ github.run_attempt }}` artifact (TRX reports and `*.database.txt` fixture evidence) from `dotnet-tests` into `TestResults/gxp`, then `Generate Compliance Reports` runs `node scripts/run-cli.js gxp sync --results-dir TestResults/gxp`, which writes a preview of the RTM and IQ/OQ/PQ report to `TestResults/gxp/preview/` without re-running `dotnet test` and fails on unknown requirement IDs, failing tagged tests, missing `*.database.txt` metadata and skipped database tests; it writes `docs/SDLC` only with `CADENCE_GXP_SNAPSHOT=1` (where `BrowserCorrectionReachesTheDatabaseWithItsReason` is also mandatory, as verified in `production-pipeline.yml`). `Check GxP Snapshot Policy` runs `node scripts/run-cli.js check gxp-snapshot` with `--base "origin/$BASE_REF"` on pull requests and `--push-before "$BEFORE_SHA"` on pushes, refusing changes to the committed RTM, IQ/OQ/PQ report or `docs/SDLC/runs/` across feature branches and direct pushes to `main` or `release/*` unless `CADENCE_GXP_SNAPSHOT=1` (ADR-2532). With `CADENCE_GXP_SNAPSHOT=1` it instead compares the regenerated documents with the snapshot (`cadence gxp diff`, which ignores the evidence block naming the tested revision, time, database and runner).
11. **CI Gate** (`ci-gate`): runs with `if: always()` and depends on all 11 validation jobs (`actionlint`, `lint-and-static`, `dotnet-quality`, `native-aot-build`, `docs-build`, `security`, `container-security`, `unit-tests`, `dotnet-tests`, `accessibility-e2e`, `compliance`). It fails closed on unapproved `workflow_dispatch` refs (outside `refs/heads/main`, `refs/heads/release/*`, and `refs/tags/v*`), fails whenever any required upstream job (`actionlint`, `lint-and-static`, `dotnet-quality`, `native-aot-build`, `docs-build`, `security`, `unit-tests`, `dotnet-tests`, `accessibility-e2e`, `compliance`) fails, cancels, or skips, and fails on `container-security` failure or cancellation while allowing `container-security` to skip on pull requests that touch no container or dependency inputs.
12. **Classify Change** (`classify`, pull requests) and **Enable Automerge** (`automerge`, pull requests): `classify` labels documentation-only pull requests (`is_safe=true`) and detects container/dependency changes (`container_scan=true`); `automerge` waits on `classify` (`is_safe == 'true'`) and `ci-gate` (`needs.ci-gate.result == 'success'`) before running `gh pr merge --auto --squash` with `GITHUB_TOKEN`.

### Branch rulesets and local reconciliation

`.github/rulesets/main.json` (`refs/heads/main`) and `.github/rulesets/release_branches.json` (`refs/heads/release/*`) restrict repository-administrator bypasses (`actor_id: 5`, `RepositoryRole`) to `bypass_mode: "pull_request"` (rejecting `"always"` direct-push bypasses), enforce `strict_required_status_checks_policy: true`, non-fast-forward, deletion, and code-owner pull-request review protections, and require only two GitHub Actions (`integration_id: 15368`) checks: `CI Gate` (`ci.yml`) and `Check for Merge Conflicts` (`conflict-check.yml`), decoupling branch protection rules from internal CI job refactors. `.github/rulesets/main.json` also declares a `merge_queue` rule (`SQUASH`, `ALLGREEN`), and both `ci.yml` and `conflict-check.yml` subscribe to `merge_group` triggers alongside `pull_request`. `.github/rulesets/version_tags.json` enforces `creation`, `required_signatures`, `deletion`, and `non_fast_forward` on `refs/tags/v*` with `bypass_actors` pinned to release admins (`actor_id: 5`, `actor_type: "RepositoryRole"`, `bypass_mode: "always"`). The `rulesets` quality gate (`pnpm cadence check rulesets`, and against staged index blobs in `pnpm cadence check --pre-commit`) fails closed if `.github/rulesets` is missing and verifies ruleset JSON schema, `pull_request`-only branch bypasses, release-admin tag signing/creation/deletion/non-fast-forward protections, `merge_queue` parameters, strict status check policy, unconditional `CI Gate` upstream job coverage, and `pull_request` + `merge_group` workflow parity (`pnpm cadence rulesets --dry-run` also validates `CI Gate` upstream job coverage when `.github/rulesets` is absent). Maintainers preview and reconcile rulesets with admin credentials via `pnpm cadence rulesets --dry-run` and `pnpm cadence rulesets` (`gh api` sync; fails non-zero on API or permission errors): `--profile paused-actions` (the default when hosted runners are paused) applies deletion, non-fast-forward, pull-request review, `pull_request` branch bypass, and release-admin tag rules while omitting `required_status_checks` and `merge_queue` so paused runners do not deadlock PRs, whereas `--profile active-actions` reconciles the full declarative ruleset payload including status checks and merge queue enforcement.

`native-aot-build` in `ci.yml` along with `production-pipeline.yml` and `deploy-docs.yml` cache `./bin/cadence` via `actions/cache` (keyed on global MSBuild files, `packages/cli/src/**`, and all `Cadence.Cli` `ProjectReference` trees), while downstream CLI jobs in `ci.yml` (`lint-and-static`, `docs-build`, `security`, and `compliance`) download the run-scoped `cadence-cli-${{ github.run_id }}-${{ github.run_attempt }}` artifact produced by `native-aot-build`. Every active `actions/setup-dotnet` step hashes `global.json`, `Directory.Build.props`, `Directory.Build.targets`, `Directory.Packages.props`, `NuGet.Config`, and `**/*.csproj`. Both `production-pipeline.yml` and `deploy-docs.yml` accept `on: workflow_call` only from `ci.yml` on pushes or ref-guarded `workflow_dispatch` runs (where `cancel-in-progress` is disabled so release evidence runs complete): `release-and-archive` (`production-pipeline.yml`, on `main`, `release/*`, and `v*` tags, gated on all 11 validation jobs and forwarding `gxp-test-evidence-${{ github.run_id }}-${{ github.run_attempt }}`, `gxp-browser-test-evidence-${{ github.run_id }}-${{ github.run_attempt }}`, and `cadence-cli-${{ github.run_id }}-${{ github.run_attempt }}` into `gxp snapshot --results-dir TestResults/gxp`, 400-day evidence archiving, GHCR digest-pinned container publishing, and immutable GitHub Releases on `v*` tags) and `deploy-docs` (`deploy-docs.yml`, on `main`, gated on all 11 validation jobs independently of `release-and-archive` so documentation publishing and release archiving run in parallel). Verify container changes locally before pushing with `pnpm cadence check hadolint` and `pnpm cadence ci --job container-security` (which builds `gateway`, `kernel-api`, `sce-python`, and `sce-r` and runs `trivy image --exit-code 1 --ignore-unfixed --pkg-types os,library --severity CRITICAL,HIGH` on each image). Verify dependency and container pin alignment across MSBuild properties (`Directory.Build.props`, `Directory.Packages.props`, `Directory.Build.targets`), the `pnpm-workspace.yaml` `catalog:`, `.config/dotnet-tools.json`, statistical Dockerfiles, and `.github/dependabot.yml` (ADR-2527) with `dotnet restore Cadence.sln && dotnet build Cadence.sln`, `pnpm install --frozen-lockfile && pnpm cadence check dependencies`, and `dotnet test tests/Cadence.UnitTests/Cadence.UnitTests.csproj --filter FullyQualifiedName~ContainerImagePinTests`.

> [!IMPORTANT]
> GitHub Actions runs `.github/workflows/ci.yml` and `.github/workflows/conflict-check.yml` on pull requests, `merge_group` runs, and pushes (`main`, `release/*`, and `v*` tags). Before pushing or merging, run `pnpm cadence ci` (or `make ci`) locally: it fetches `origin/main` (unless `--offline` is passed for air-gapped debugging), synthesizes a merged commit via `git merge-tree --write-tree` (failing immediately with conflicted file paths on conflict), and runs the pull-request jobs above (starting with `actionlint`, including diff-scoped `container-security`) inside a disposable detached worktree under `Path.GetTempPath()` while reusing read-only `.cadence` toolchains from your checkout without mutating it. It requires `actionlint`, `hadolint`, and `shellcheck` (in `.cadence/bin` or on `PATH`),
> `detect-secrets-hook` (in `.cadence/venv`, `.venv` or on `PATH`), `bash` on `PATH`, `docker` (with a running Docker daemon) and `trivy` when container or dependency files change (or with `--job container-security`), plus PostgreSQL 18 (`*.database.txt` evidence and full database test execution) for `.NET` tests and `compliance`, and fails when any required binary, daemon or
> database evidence is missing unless `--allow-missing-tools` or `--allow-db-skip` (or `--allow-skip` for both) is passed ([cli.md](cli.md#cadence-ci)). A full run takes about 20 minutes:
> `CADENCE_TEST_POSTGRES=<connection string> pnpm cadence ci`. Without a terminal (an AI agent, a script, a pipe, a git
> hook) the CLI prints plain text, so its output can be redirected to a file as it is.

## Quality gates

`pnpm cadence check` runs every gate in `packages/cli/src/Services/QualityGates.cs`, the one registry of quality gates. Revision-scoped gates resolve staged, branch (`--base <ref>`), push (`--push-before <sha>`), and full-repository (`git ls-files -z`) scopes in C# through `GitRevisionScopeService` rather than shell pipelines. The pre-commit hook runs `pnpm cadence check --pre-commit` (below), and CI partitions the registry across existing runtime jobs with `--exclude` (`actionlint` runs in `actionlint`; `prettier`, `eslint`, `hadolint`, and `api-clients` run in `lint-and-static`; `detect-secrets` and `vulnerabilities` run in `security`; `public-bundle` runs in `docs-build` and `deploy-docs.yml` after static bundle compilation; `architecture-tests` runs as its own step in `dotnet-quality`; `unit-tests` runs inside `dotnet-tests`; and `dotnet-quality` runs `check --exclude prettier --exclude eslint --exclude actionlint --exclude hadolint --exclude detect-secrets --exclude api-clients --exclude vulnerabilities --exclude public-bundle --exclude architecture-tests --exclude unit-tests`, passing `--base "origin/$BASE_REF"` on pull requests and `--push-before "$BEFORE_SHA"` on pushes). Run one gate with `pnpm cadence check <gate>`; an unknown gate name (or unknown `--exclude` gate) fails. Contributors running pre-commit hooks, `pnpm cadence check` or `pnpm cadence ci` locally must restore `Cadence.sln` (`dotnet restore Cadence.sln`), provision local guardrails via `./scripts/setup_wizard.sh --minimal` (or `./scripts/setup_wizard.ps1 -Minimal`, which installs `detect-secrets==1.5.0` into `.cadence/venv` and SHA-256-verified `actionlint` v1.7.12, `hadolint` v2.15.1, and `shellcheck` v0.11.0 into `.cadence/bin`), and build the static bundles (`pnpm --filter ui build && pnpm docs:build && pnpm docs:stage-demos`) before running `check public-bundle` directly (unscoped `cadence check` skips `public-bundle` only when all three `dist/` directories are absent and fails closed on partial `dist/` output, while direct `check public-bundle` always fails closed), because `prettier`, `eslint`, `actionlint`, `hadolint`, `detect-secrets`, `vulnerabilities`, and `public-bundle` all fail closed whenever their toolchains or inputs are missing. The table is generated from the registry by `pnpm cadence generate-cli-docs`, and the `cli-docs` gate fails when it is stale. [cli.md](cli.md#cadence-check) lists each gate's other names and what the pre-commit hook does with it. `QualityGateRegistryTests` runs every gate against a fixture that must make it fail, so a gate that cannot fail does not get in.

`pnpm cadence check rtm` (or `gxp-rtm-validate`) validates the requirement tags and integrity stamps without regenerating the matrix; it requires the matrix's test mapping to be current only with `CADENCE_GXP_SNAPSHOT=1`. `pnpm cadence check gxp-snapshot` (or `gxp-snapshot-guard`) runs the snapshot guard. `pnpm cadence check baseline-ratchet` (or `baselines`) runs the baseline ratchet ([docs/TESTING.md](TESTING.md#ratchet-baselines)); it runs inside `pnpm cadence check`, so CI's `Run Cadence quality sentinels` step and `cadence ci` run it too.

### Dual-layer source and public bundle gates (ADR-2386, ADR-2497, ADR-2550)

- **Layer 1 (`deid` and `security` on tracked source):** `DeidComplianceService` scans application code, authored portal docs (`docs/`), staged root portal documents (`README.md`, `ARCHITECTURE.md`, `AGENTS.md`, `CONTEXT.md`, `CONTRIBUTING.md`, `SECURITY.md`, `SUPPORT.md`, `LICENSE`), `.vue` templates, and `stores/` (fulfilling ADR-2386). Only test suites (`tests/`), tooling/infrastructure folders (`scripts/`, `docker/`, `packages/deid/`), vendored clinical standards (`docs/CDISC/`, `docs/NCI/`), generated OpenAPI/EF schema outputs (`docs/openapi/`, `docs/schema/`), and GxP qualification snapshots (`docs/SDLC/runs/`, `Requirements_Traceability_Matrix.md`, `IQ_OQ_PQ_Execution_Report.md`) are excluded from source DEID scans to protect snapshot integrity. `SecretScanner` (`check security`) scans source files including `.vue` templates and `scripts/` (such as `scripts/build-docs.js` and `scripts/stage-portal-demos.js`), and `.secrets.baseline` (`clean-secrets`) does not exclude `dist/`.
- **Layer 2 (`public-bundle` on built static outputs):** `PublicBundleValidatorService` (`pnpm cadence check public-bundle` / `validate-public-bundle`) scans every generated text file in `docs/.vitepress/dist` (including co-hosted `/demo/` and `/subject-portal/` subpaths), `apps/web/dist`, and `apps/subject-portal/dist` with **zero comment or pragma exemptions** (`deid-ignore`, `deid: ignore`, and `pragma: allowlist` are ignored), failing closed if any bundle is missing or contains national identifiers, unapproved emails, secrets, external assets, executable local backend URLs (`localhost`, `127.0.0.1`, `0.0.0.0`), or missing/permissive `Content-Security-Policy` `<meta>` directives.

## Pre-commit hook

`scripts/setup_wizard.sh`, `scripts/setup_wizard.ps1`, and `pnpm install` (`scripts/setup-git-hooks.js`) point git at `.githooks/` (`git config core.hooksPath .githooks`), and the setup wizards provision `detect-secrets==1.5.0` in `.cadence/venv` plus SHA-256-verified `actionlint` (`1.7.12`), `hadolint` (`2.15.1`), and `shellcheck` (`0.11.0`) binaries in `.cadence/bin`. On Linux, macOS, and Windows (via Git for Windows `sh`), `.githooks/pre-commit` is a fail-closed POSIX launcher that sources `scripts/resolve_dotnet_env.sh` to verify `node` and a `global.json`-compatible `.NET 10` SDK are active (retaining `$HOME/.dotnet/tools` on `PATH` and promoting `$DOTNET_ROOT`, `$HOME/.dotnet`, or `%LOCALAPPDATA%\Microsoft\dotnet` only when `PATH` lacks `.NET 10` and `dotnet`, `host/fxr`, and `sdk/10.*` all exist) before delegating to `node scripts/run-cli.js check --pre-commit`.

`cadence check --pre-commit` executes every gate in `QualityGates.cs` fail-closed against staged Git index blobs (`GitIndexReader` via `git cat-file --batch`, without acquiring `.git/index.lock` or mutating working-tree files), treating deletion-only and clean merge commits (`TargetFiles = []`) as a no-op across file-scoped gates (with the quick variants listed in [cli.md](cli.md#cadence-check)):

- `dotnet-format` validates materialized staged C# and `.editorconfig` blobs, and `dotnet-format-style` checks staged C# files while failing closed if `dotnet` is missing or unstaged edits overlap MSBuild inputs.
- `prettier` and `eslint` stream staged JS, TS, Vue, CSS, JSON, Markdown, and YAML blobs over `stdin` (and fail closed if `pnpm` or `node_modules` is missing).
- `actionlint` and `hadolint` validate materialized staged `.github/workflows`, `.github/actions`, and `Dockerfile*` blobs using `.cadence/bin` or `PATH` (failing closed when missing).
- `workflow-security` (also `action-pinning`), `rulesets`, `yaml`, `trailing-whitespace`, `end-of-file`, `sanitizer` (read-only error reporting on lowercase `@req:prd-…` tags), and `detect-secrets` validate staged index blobs (40-char commit SHAs, `sha256:` container digests, `persist-credentials: false`, least-privilege permissions, ref-guarded typed `workflow_dispatch` inputs, declarative `.github/rulesets/*.json` presence, `pull_request`-only branch bypasses, `merge_queue` policy, and `CI Gate` / `merge_group` workflow parity, YAML syntax, whitespace/EOF hygiene, and secrets against `.secrets.baseline` via `.cadence/venv`, `PATH`, or `uvx`) without touching unstaged working-tree edits.
- `schema-doc` runs the drift check when staged files include Entity Framework entities, migrations, configurations, or `docs/schema`; `openapi` exports specs only for the services the staged C# files touch (both failing closed if unstaged edits overlap MSBuild/spec inputs); `demo-manifest` validates materialized staged seed and fixture blobs only when staged files touch `packages/demo-fixtures`, `DevelopmentDemoData.cs`, `ExecutionDbSeeder.cs`, or `docker/cadence-realm.json`; `adrs` checks staged files for architectural changes while accepting ADRs already added on the branch; and `gxp-snapshot` and `baseline-ratchet` check the staged copies against `HEAD` (`baseline-ratchet` admits staged growth when `CADENCE_BASELINE_GROWTH="<reason>"` is set, requiring a matching `Baseline-Growth: <path> - <reason>` trailer on the commit). `merge-readiness`, `public-bundle`, `branch-freshness`, `architecture-tests`, and `unit-tests` are skipped on commit so local commits stay fast and offline; `pnpm cadence check`, `make verify`, and CI run every gate in full.

There is no pre-push hook. Requirement tags and test results are checked in CI by the compliance job; run `pnpm cadence gxp sync` before pushing test changes, and commit nothing it generates.

```bash
# Verify environment readiness and run all guardrails without committing
pnpm cadence doctor
pnpm cadence check

# Enable the hooks by hand if setup was skipped
git config core.hooksPath .githooks
```

Don't bypass the hook with `--no-verify`; fix the failing gate instead.
