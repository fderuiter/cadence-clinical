# Continuous Integration

How CI is set up, which checks run where, and how to reproduce and fix each failure locally. The Cadence CLI runs as `pnpm cadence <command>` (a wrapper for `dotnet run --project packages/cli/src/Cadence.Cli.csproj --`).

## Workflows

| Workflow                  | Runs on                                                    | What it does                                                                                                                                                                   |
| ------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `ci.yml`                  | Pull requests and pushes to `main`                         | Style, lint and frontend builds, security audit, .NET tests (including kernel consumer contracts), frontend unit and Playwright E2E accessibility tests, GxP compliance checks |
| `conflict-check.yml`      | Pull requests (opened, synchronize, reopened)              | Fails when the PR conflicts with `main` (shallow checkout, no `.NET` install)                                                                                                  |
| `production-pipeline.yml` | Called by `ci.yml` on pushes to `main`, or manual dispatch | Vulnerability audit, runs the full test suite against pinned PostgreSQL 18 via `gxp snapshot`, uploads reports with SHA-256 checksums and SLSA provenance                      |
| `deploy-docs.yml`         | Path-filtered pushes to `main`, or manual dispatch         | Builds and publishes the static VitePress portal and demo UI to GitHub Pages (`CADENCE_DOCS_SKIP_CHECKS=1`) with SHA-256 checksums and SLSA provenance                         |

### `ci.yml` jobs

1. **Workflow Action Pinning & Actionlint Gate** (`actionlint`): runs `rhysd/actionlint` and `python3 scripts/check-action-pinning.py` to enforce GitHub Actions supply-chain security (pinning third-party action usages to full 40-character commit SHAs) and workflow YAML syntax.
2. **Lint and Static Verification** (`lint-and-static`): installs the pnpm workspace and runs `pnpm build` (compiling `packages/ui`, `apps/web`, and `apps/subject-portal`), runs Prettier and ESLint across frontend packages, Hadolint on Dockerfiles, ShellCheck on `*.sh` scripts, `bash tests/test_installer_checksums.sh` (verifying `.NET` installer SHA-256 checksum enforcement), `check markdown`, and `check api-clients` (`ApiClientValidatorService`, typechecking generated web OpenAPI types and clients).
3. **.NET Quality & Sentinel Checks** (`dotnet-quality`): builds `Cadence.sln`, runs `cadence check --exclude api-clients --exclude vulnerabilities` (executing the remaining 25 gates once, including `dotnet-format`, `dotnet-format-style`, `adrs`, `codeowners`, `schema-doc`, `openapi`, `rtm`, and `duplication`), runs `Cadence.ArchitectureTests` (ArchUnitNET), and uploads `duplication_summary.json` (`duplication-summary`).
4. **Native AOT Compilation** (`native-aot-build`) and **Documentation Compilation** (`docs-build`): publishes `Cadence.Cli` as a Native AOT `linux-x64` binary (failing on any trim or AOT warning) and compiles the documentation portal (`pnpm docs:build` with `CADENCE_DOCS_SKIP_CHECKS=1`).
5. **Security and Vulnerability Audit** (`security`): static security audit (`audit-security`), fail-closed NuGet, pnpm and Python (`pip-audit==2.10.1` in an isolated `venv` after `dotnet restore Cadence.sln`) vulnerability audit (`check vulnerabilities`), secret baseline immutability (`clean-secrets` and `git diff --exit-code .secrets.baseline`), `detect-secrets-hook`, and the `deid` compliance scan.
6. **Container Build & Vulnerability Scan** (`container-security`): builds `gateway`, `kernel-api`, `sce-python` and `sce-r` across a parallel matrix and runs fail-closed Trivy (`CRITICAL,HIGH`, `--ignore-unfixed`, exit code `1`) with distinct SARIF uploads (`trivy-<target>`) on pushes and on container or dependency pull requests.
7. **.NET 10 C# xUnit Verification** (`dotnet-tests`): `dotnet build` (warnings are errors), then `dotnet test Cadence.sln` (including `packages/kernel/consumer-tests/Cadence.Kernel.ConsumerTests`) with `CADENCE_TEST_EVIDENCE_DIR=${{ github.workspace }}/TestResults/gxp` against a PostgreSQL 18 service container pinned to `PostgresTestImage.Image` (`CADENCE_TEST_POSTGRES`), uploading `tests/**/TestResults/*.trx`, `packages/**/TestResults/*.trx`, and `*.database.txt` fixture metadata in `trx-report-dotnet`. Locally either `CADENCE_TEST_POSTGRES` or `CADENCE_TEST_DOCKER=1` works for every database fixture ([TESTING.md](TESTING.md#tests-that-need-postgresql)), and `cadence ci` fails when any integration or E2E test was skipped or did not execute, unless `--allow-skip` is given. In GitHub Actions, `dotnet-tests` runs `scripts/test-check-database-test-results.sh` and `scripts/check-database-test-results.sh`, verifying that both `tests/Cadence.IntegrationTests` and `tests/Cadence.E2ETests` produced TRX reports and failing on any `NotExecuted` database test except the opt-in lineage benchmark and browser correction check (`DatabaseTestEvidence.OptInTests`); `test_outcome` waits on that step, blocking `compliance` on failure.
8. **Frontend Unit Tests** (`unit-tests`): Vitest across the pnpm workspace.
9. **Parallel E2E Accessibility Testing** (`accessibility-e2e`): runs on pull requests and pushes to `main` (and gates `automerge`), executing Playwright accessibility E2E suites for `subject-portal` and `web` (failing closed with exit code `1` if Playwright browser installation fails three times), plus `BrowserCorrectionReachesTheDatabaseWithItsReason` (`tests/Cadence.IntegrationTests`) against PostgreSQL 18 with `CADENCE_TEST_BROWSER=1`.
10. **GxP Compliance & Qualification Reporting** (`compliance`): downloads the `trx-report-dotnet` artifact (TRX reports and `*.database.txt` fixture evidence) from `dotnet-tests` into `TestResults/gxp`, then `Generate Compliance Reports` runs `node scripts/run-cli.js gxp sync --results-dir TestResults/gxp`, which writes a preview of the RTM and IQ/OQ/PQ report to `TestResults/gxp/preview/` without re-running `dotnet test` and fails on unknown requirement IDs, failing tagged tests and skipped database tests; it writes `docs/SDLC` only with `CADENCE_GXP_SNAPSHOT=1`. `Check GxP Snapshot Policy` runs `node scripts/run-cli.js check gxp-snapshot`, which fails when the branch changes the committed RTM, IQ/OQ/PQ report or `docs/SDLC/runs/` (ADR-2532). With `CADENCE_GXP_SNAPSHOT=1` it instead compares the regenerated documents with the snapshot (`cadence gxp diff`, which ignores the evidence block naming the tested revision, time, database and runner).

Jobs that run `node scripts/run-cli.js` across `ci.yml`, `production-pipeline.yml`, and `deploy-docs.yml` cache `./bin/cadence` via `actions/cache` (keyed on global MSBuild files, `packages/cli/src/**`, and all `Cadence.Cli` `ProjectReference` trees), and every active `actions/setup-dotnet` step hashes `global.json`, `Directory.Build.props`, `Directory.Packages.props`, and `**/*.csproj`. Only the production pipeline (`release-and-archive`) runs exclusively on pushes to `main`. Documentation publishing runs independently in `deploy-docs.yml` when portal, docs, shared UI or demo paths change on `main` (or via manual `workflow_dispatch`). While GitHub Actions is paused, verify container changes locally with Hadolint (`find docker -type f -name "Dockerfile*" -exec hadolint --failure-threshold error {} +`), container builds (`docker build -t cadence-gateway:latest -f docker/Dockerfile.dotnet --build-arg APP_NAME=gateway .`, `docker build -t cadence-kernel-api:latest -f docker/Dockerfile.dotnet --build-arg APP_NAME=kernel-api .`, `docker build -t cadence-sce-python:latest -f docker/sce/python/Dockerfile docker/sce/python`, `docker build -t cadence-sce-r:latest -f docker/sce/r/Dockerfile docker/sce/r`), and Trivy (`trivy image --exit-code 1 --ignore-unfixed --pkg-types os,library --severity CRITICAL,HIGH cadence-gateway:latest`).

> [!IMPORTANT]
> GitHub Actions does not run jobs for this repository until 2027: every check on a pull request fails within seconds
> without running. Until then, run `pnpm cadence ci` (or `make ci`) before merging. It runs the jobs above on your
> machine with the same commands and needs PostgreSQL for the .NET tests ([cli.md](cli.md#cadence-ci)). A full run
> takes about 20 minutes: `CADENCE_TEST_POSTGRES=<connection string> pnpm cadence ci`. Without a terminal (an AI agent,
> a script, a pipe, a git hook) the CLI prints plain text, so its output can be redirected to a file as it is.

## Quality gates

`pnpm cadence check` runs every gate in `packages/cli/src/Services/QualityGates.cs`, the one registry of quality gates. The pre-commit hook runs a quicker variant (below), and CI partitions the registry across existing runtime jobs with `--exclude` (`api-clients` runs in `lint-and-static`, `vulnerabilities` runs in `security`, and `dotnet-quality` runs `check --exclude api-clients --exclude vulnerabilities`). Run one gate with `pnpm cadence check <gate>`; an unknown gate name (or unknown `--exclude` gate) fails. While GitHub Actions remains disabled until 2027, contributors running pre-commit hooks, `pnpm cadence check` or `pnpm cadence ci` locally must restore `Cadence.sln` (`dotnet restore Cadence.sln`) and provision `pip-audit` in a virtual environment (`python3 -m venv .venv && .venv/bin/python -m pip install --upgrade pip pip-audit==2.10.1` or on `PATH`), because the `vulnerabilities` gate fails closed whenever `.NET`, `pnpm` or `pip-audit` scanners are missing, unrestored or return errors. The table is generated from the registry by `pnpm cadence generate-cli-docs`, and the `cli-docs` gate fails when it is stale. [cli.md](cli.md#cadence-check) lists each gate's other names and what the pre-commit hook does with it. `QualityGateRegistryTests` runs every gate against a fixture that must make it fail, so a gate that cannot fail does not get in.

`pnpm cadence check` runs these 27 gates in this order:

| Gate                  | What it checks                                                                                                                                                                                  |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dotnet-format`       | Whitespace formatting against `.editorconfig` (`dotnet format whitespace`)                                                                                                                      |
| `dotnet-format-style` | Roslyn code-style rules (`dotnet format style`)                                                                                                                                                 |
| `clean-secrets`       | Normalizes `.secrets.baseline`; fails when it is not valid JSON (CI then checks that it did not change)                                                                                         |
| `duplication`         | Duplicated code blocks over 15 normalized lines involving a C# file                                                                                                                             |
| `cli-docs`            | `docs/cli.md` documents every command in `Program.cs`, and the gate tables in `docs/cli.md` and `docs/CI.md` match this registry                                                                |
| `adrs`                | ADR schema, `docs/adr/index.md` consistency, and an ADR for architectural changes                                                                                                               |
| `arch-drift`          | `docker/docker-compose.yml` exists and declares services; services missing from the architecture docs are warnings                                                                              |
| `sanitizer`           | Requirement tags in Markdown are upper case (`@req:PRD-…`); it fixes them and fails so the fix is staged                                                                                        |
| `markdown`            | Markdown structure, links, and paths into .NET test project folders (`tests/Cadence.*`) that no longer exist                                                                                    |
| `env-vars`            | Environment variables read in code are in `.env.example` and `docs/ENVIRONMENT_VARIABLES.md`                                                                                                    |
| `dev-env`             | Service ports in `docs/LOCAL_DEV_ENVIRONMENT.md` match the gateway and the Aspire AppHost                                                                                                       |
| `readmes`             | Each directory under `apps/` and `packages/` has a README with a title                                                                                                                          |

| `imports`             | No `using` of another service's namespace across `apps/<service>`                                                                                                                               |
| `security`            | Hard-coded secret patterns (private keys, AWS secret keys)                                                                                                                                      |
| `deid`                | PHI/PII in tracked files outside tests, docs, scripts and similar folders (all 14 detector categories), ratcheted by `.deid-baseline.txt`; a line that is not PHI takes a `deid-ignore` comment |
| `openapi`             | `docs/openapi` matches what the .NET services serve, and `docs/api` matches `docs/openapi`                                                                                                      |
| `api-clients`         | The web API types are generated from the current `docs/openapi`, and the web API clients typecheck against them                                                                                 |
| `schema-doc`          | `docs/schema` matches the EF Core models                                                                                                                                                        |
| `path-patterns`       | No `tmp`, `temp`, `scratch` or `old_src` directories, `.vue` files only under `apps/` and `packages/`, `.sh` files only under `scripts/`                                                        |
| `query-linter`        | No interpolated SQL string passed to `FromSqlRaw` or `ExecuteSqlRaw`, and no comparison with a boolean literal                                                                                  |
| `vulnerabilities`     | NuGet, pnpm and Python dependency vulnerabilities not exempted by a valid `docs/SDLC/vulnerability_exclusions_ledger.json` entry (fails closed on missing or broken scanners)                   |
| `dependencies`        | `apps/web/package.json` lists no client-side crypto package (`node-forge`, `elliptic`, `jose`)                                                                                                  |
| `doc-index`           | Every Markdown document under `docs/` is listed in `docs/DOCUMENTATION_INDEX.md`                                                                                                                |
| `rtm`                 | Requirement tags name known requirements and sit on test methods, and the generated documents match their integrity stamps and are not drafts                                                   |
| `gxp-snapshot`        | The branch does not change the generated RTM, IQ/OQ/PQ report or `docs/SDLC/runs/` unless `CADENCE_GXP_SNAPSHOT=1` (ADR-2532)                                                                   |
| `baseline-ratchet`    | No ratchet baseline (`*.baseline.txt`, `.deid-baseline.txt`, `.secrets.baseline`) gained an entry since the `origin/main` merge base, unless a commit has a `Baseline-Growth:` trailer          |

`pnpm cadence check rtm` (or `gxp-rtm-validate`) validates the requirement tags and integrity stamps without regenerating the matrix; it requires the matrix's test mapping to be current only with `CADENCE_GXP_SNAPSHOT=1`. `pnpm cadence check gxp-snapshot` (or `gxp-snapshot-guard`) runs the snapshot guard. `pnpm cadence check baseline-ratchet` (or `baselines`) runs the baseline ratchet ([docs/TESTING.md](TESTING.md#ratchet-baselines)); it runs inside `pnpm cadence check`, so CI's `Run Cadence quality sentinels` step and `cadence ci` run it too.

## Pre-commit hook

`scripts/setup_wizard.sh` points git at `.githooks/` (`git config core.hooksPath .githooks`). The `pre-commit` hook (`pre-commit.ps1` on Windows) runs:

1. `dotnet format Cadence.sln --verify-no-changes --include <staged .cs files>`, skipped when no C# file is staged.
2. `pnpm cadence check --pre-commit`: every gate, limited to the staged files where a gate takes files, with the shortcuts listed in [cli.md](cli.md#cadence-check): the two format gates are skipped (step 1 covers the staged C# files), the `schema-doc` gate runs the drift check when staged files include Entity Framework entities, migrations, or configurations, the `openapi` gate exports specs only for the services the staged C# files touch, and the `gxp-snapshot` and `baseline-ratchet` gates check the staged copies; `baseline-ratchet` admits staged growth when `CADENCE_BASELINE_GROWTH="<reason>"` is set, and the commit then needs a `Baseline-Growth: <reason>` trailer. `pnpm cadence check`, `make verify` and CI run every gate in full.

Additionally, `.pre-commit-config.yaml` configures `rhysd/actionlint` and local `action-pinning-check` (`scripts/check-action-pinning.py`) hooks to ensure all GitHub Actions references in `.github/workflows/` are syntax-checked and pinned to 40-character commit SHAs.

There is no pre-push hook. Requirement tags and test results are checked in CI by the compliance job; run `pnpm cadence gxp sync` before pushing test changes, and commit nothing it generates.

```bash
# Run the same checks without committing
dotnet format Cadence.sln --verify-no-changes
pnpm cadence check
python3 scripts/check-action-pinning.py

# Enable the hooks by hand if setup was skipped
git config core.hooksPath .githooks
```

Don't bypass the hook with `--no-verify`; fix the failing gate instead.

## CI failure runbook

CI runs in `.github/workflows/ci.yml`. `pnpm cadence ci` reproduces the whole workflow; each check can also be reproduced on its own with the command in the last column.

| Failing job or step                                    | Usual cause                                                                                      | Reproduce and fix locally                                                                                                                                                                                                                                  |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Workflow Action Pinning & Actionlint Gate              | Third-party action not pinned to 40-char SHA or actionlint YAML error                            | `python3 scripts/check-action-pinning.py` and `pre-commit run actionlint --all-files`                                                                                                                                                                      |
| Lint and Static › Build frontend workspace             | Vite or Rollup build failure in `packages/ui`, `apps/web` or `apps/subject-portal`               | `pnpm build`                                                                                                                                                                                                                                               |
| Lint and Static › Run frontend style and lint          | ESLint or Prettier findings in `apps/web`, `apps/subject-portal` or `packages/ui`                | `pnpm format` and `pnpm -r lint`                                                                                                                                                                                                                           |
| Lint and Static › Validate web API clients             | Stale generated OpenAPI TypeScript types or web client type error                                | `pnpm --filter web run generate:api` and `pnpm cadence check api-clients`                                                                                                                                                                                  |
| Lint and Static › Run Hadolint or ShellCheck           | Dockerfile or shell script findings                                                              | `find docker -type f -name "Dockerfile*" -exec hadolint --failure-threshold error {} +`, `shellcheck <script>`                                                                                                                                             |
| Lint and Static › Run installer checksum tests         | SHA-256 verification regression in `setup_dotnet_env.sh` or `setup_dotnet_wizard.sh`             | `bash tests/test_installer_checksums.sh`                                                                                                                                                                                                                   |
| .NET Quality › Run Cadence quality sentinels           | A quality gate (`dotnet-format`, `openapi`, `adrs`, `rtm`, etc.) failed                          | `pnpm cadence check <gate>` (for formatting: `dotnet format Cadence.sln`, for OpenAPI: `pnpm cadence sync-openapi-spec && pnpm cadence generate-api-docs`, for ADRs: `pnpm cadence scaffold adr "<title>"`)                                                |
| .NET Quality › Run architecture tests                  | A layer dependency rule was broken                                                               | `dotnet test tests/Cadence.ArchitectureTests/Cadence.ArchitectureTests.csproj`                                                                                                                                                                             |
| Native AOT Compilation › Publish the CLI as Native AOT | The CLI, or code it calls, raised a trim or AOT warning (IL2xxx/IL3xxx)                          | `dotnet publish packages/cli/src/Cadence.Cli.csproj -c Release -r linux-x64`; fix the call, never add `NoWarn`                                                                                                                                             |
| Container Build & Vulnerability Scan                   | Broken Dockerfile build or fixable `CRITICAL`/`HIGH` OS or library CVE                           | `docker build -t cadence-gateway:latest -f docker/Dockerfile.dotnet --build-arg APP_NAME=gateway .` and `trivy image --exit-code 1 --ignore-unfixed --pkg-types os,library --severity CRITICAL,HIGH cadence-gateway:latest`                                |
| Security › Run dependency audit                        | A vulnerable NuGet, pnpm or Python package, an un-restored `Cadence.sln`, or missing `pip-audit` | Run `dotnet restore Cadence.sln` and `python3 -m venv .venv && .venv/bin/python -m pip install --upgrade pip pip-audit==2.10.1`, then `pnpm cadence check vulnerabilities`; upgrade in `Directory.Packages.props`, `package.json` or `pnpm-workspace.yaml` |
| Frontend Unit Tests                                    | A Vitest failure                                                                                 | `pnpm -r test`                                                                                                                                                                                                                                             |
| .NET 10 C# xUnit Verification                          | A build warning, xUnit failure, missing TRX or skipped PostgreSQL test                           | `dotnet build Cadence.sln`, `dotnet test Cadence.sln`, and `bash scripts/check-database-test-results.sh`                                                                                                                                                   |
| Parallel E2E Accessibility › Playwright E2E Suites     | Subject Portal or Web accessibility/workflow E2E failure                                         | `pnpm --filter subject-portal test:e2e` and `pnpm --filter web test:e2e`                                                                                                                                                                                   |
| Parallel E2E Accessibility › Browser-to-Database Test  | Browser observation correction failed against PostgreSQL 18                                      | `CADENCE_TEST_POSTGRES=<conn> CADENCE_TEST_BROWSER=1 dotnet test tests/Cadence.IntegrationTests/Cadence.IntegrationTests.csproj --filter FullyQualifiedName~BrowserCorrectionReachesTheDatabaseWithItsReason`                                              |
| GxP Compliance › Generate Compliance Reports           | An unknown requirement ID, a failing tagged test or a skipped database test                      | `pnpm cadence gxp sync` (or `--results-dir TestResults/gxp`) with PostgreSQL; fix the tag or test                                                                                                                                                          |
| GxP Compliance › Check GxP Snapshot Policy             | The branch changed the generated RTM, IQ/OQ/PQ report or `docs/SDLC/runs/`                       | `git checkout origin/main -- docs/SDLC/Requirements_Traceability_Matrix.md docs/SDLC/IQ_OQ_PQ_Execution_Report.md docs/SDLC/runs`; never commit them on a feature branch                                                                                   |
| Check for Merge Conflicts                              | The PR conflicts with `main`                                                                     | `git merge origin/main` and resolve                                                                                                                                                                                                                        |
