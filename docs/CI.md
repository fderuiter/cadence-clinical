# Continuous Integration

How CI is set up, which checks run where, and how to reproduce and fix each failure locally. The Cadence CLI runs as `pnpm cadence <command>` (a wrapper for `dotnet run --project packages/cli/src/Cadence.Cli.csproj --`).

## Workflows

| Workflow                  | Runs on                                                                                 | What it does                                                                                                                                                                                                                                                                                                     |
| ------------------------- | --------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ci.yml`                  | Pull requests and pushes to `main`, `release/*`, and `v*` tags                          | Style, lint and frontend builds, quality sentinels, Native AOT and docs builds, workflow and container security audits, .NET tests (including kernel consumer contracts), frontend unit and Playwright E2E accessibility tests, GxP compliance checks, `CI Gate`, safe automerge, and gated release/docs callers |
| `conflict-check.yml`      | Pull requests (opened, synchronize, reopened)                                           | Emits `Check for Merge Conflicts` and fails when the PR conflicts with its base branch (shallow checkout, no `.NET` install)                                                                                                                                                                                     |
| `production-pipeline.yml` | Called by `ci.yml` on pushes to `main`, `release/*`, and `v*` tags, or manual dispatch  | Vulnerability audit, generates stamped GxP RTM and IQ/OQ/PQ reports from verified CI test evidence (`gxp snapshot --results-dir TestResults/gxp`, or runs tests against pinned PostgreSQL 18 on manual dispatch), with SHA-256 sums and SLSA                                                                     |
| `deploy-docs.yml`         | Called by `ci.yml` on pushes to `main` (parallel to `release-and-archive`), or dispatch | Builds and publishes the static VitePress portal and demo UI to GitHub Pages (`CADENCE_DOCS_SKIP_CHECKS=1`), verifies `SHA256SUMS`, and attests the packaged Pages archive (`artifact.tar`) with SLSA provenance                                                                                                 |

### `ci.yml` jobs

1. **Workflow Action Pinning & Actionlint Gate** (`actionlint`): runs `rhysd/actionlint` (`actionlint` on `PATH` in `cadence ci`) to enforce workflow YAML syntax, while the native `workflow-security` gate (run in `dotnet-quality` and `pnpm cadence check`) enforces GitHub Actions supply-chain security across `.github/workflows/*.{yml,yaml}` and `.github/actions/**/action.{yml,yaml}` (40-character commit SHAs with inline version comments, `sha256:` digests on `docker://` references, `persist-credentials: false` on `actions/checkout`, and least-privilege workflow permissions).
2. **Lint and Static Verification** (`lint-and-static`): installs the pnpm workspace and runs `pnpm build` (compiling `packages/ui`, `apps/web`, and `apps/subject-portal`), runs Prettier and ESLint across frontend packages, Hadolint on Dockerfiles, ShellCheck on `*.sh` scripts, `bash tests/test_installer_checksums.sh` (verifying `.NET` installer SHA-256 checksum enforcement), `check markdown`, and `check api-clients` (`ApiClientValidatorService`, typechecking generated web OpenAPI types and clients).
3. **.NET Quality & Sentinel Checks** (`dotnet-quality`): builds `Cadence.sln`, runs `cadence check --exclude api-clients --exclude vulnerabilities` (executing the remaining 27 gates once, including `dotnet-format`, `dotnet-format-style`, `adrs`, `codeowners`, `workflow-security`, `rulesets`, `schema-doc`, `openapi`, `rtm`, and `duplication`), runs `Cadence.ArchitectureTests` (ArchUnitNET), and uploads `duplication_summary.json` (`duplication-summary-${{ github.run_id }}-${{ github.run_attempt }}`).
4. **Native AOT Compilation** (`native-aot-build`) and **Documentation Compilation** (`docs-build`): publishes `Cadence.Cli` as a Native AOT `linux-x64` binary (failing on any trim or AOT warning) and compiles the documentation portal (`pnpm docs:build` with `CADENCE_DOCS_SKIP_CHECKS=1`).
5. **Security and Vulnerability Audit** (`security`): static security audit (`audit-security`), fail-closed NuGet, pnpm and Python (`pip-audit==2.10.1` in an isolated `venv` after `dotnet restore Cadence.sln`) vulnerability audit (`check vulnerabilities`), secret baseline immutability (`clean-secrets` and `git diff --exit-code .secrets.baseline`), `detect-secrets-hook`, and the `deid` compliance scan.
6. **Container Build & Vulnerability Scan** (`container-security`): builds `gateway`, `kernel-api`, `sce-python` and `sce-r` across a parallel matrix and runs fail-closed Trivy (`CRITICAL,HIGH`, `--ignore-unfixed`, exit code `1`) with distinct SARIF uploads (`trivy-<target>`) on pushes and on container or dependency pull requests.
7. **.NET 10 C# xUnit Verification** (`dotnet-tests`): `dotnet build` (warnings are errors), then `dotnet test Cadence.sln --configuration Release --no-build --results-directory TestResults/gxp --logger "trx;LogFilePrefix=gxp"` (including `packages/kernel/consumer-tests/Cadence.Kernel.ConsumerTests`) with `CADENCE_TEST_EVIDENCE_DIR=${{ github.workspace }}/TestResults/gxp` against a PostgreSQL 18 service container pinned to `PostgresTestImage.Image` (`CADENCE_TEST_POSTGRES`). Diagnostic TRX reports and `*.database.txt` fixture metadata are uploaded unconditionally in `trx-report-dotnet-${{ github.run_id }}-${{ github.run_attempt }}`. Locally either `CADENCE_TEST_POSTGRES` or `CADENCE_TEST_DOCKER=1` works for every database fixture ([TESTING.md](TESTING.md#tests-that-need-postgresql)), and `cadence ci` runs `bash scripts/test-check-database-test-results.sh` and fails via `DatabaseTestEvidence` when any integration or E2E test was skipped or did not execute, unless `--allow-skip` is given. In GitHub Actions, `dotnet-tests` runs `scripts/test-check-database-test-results.sh` and `scripts/check-database-test-results.sh`, verifying that both `tests/Cadence.IntegrationTests` and `tests/Cadence.E2ETests` produced TRX reports and `*.database.txt` metadata in `TestResults/gxp` and failing on any `NotExecuted` database test except the opt-in lineage benchmark and browser correction check (`DatabaseTestEvidence.OptInTests`). Only after that gate passes does `dotnet-tests` upload `TestResults/gxp` as `gxp-test-evidence-${{ github.run_id }}-${{ github.run_attempt }}`; `test_outcome` waits on both the gate and evidence upload, blocking `compliance` and downstream release workflows on failure.
8. **Frontend Unit Tests** (`unit-tests`): Vitest across the pnpm workspace.
9. **Parallel E2E Accessibility Testing** (`accessibility-e2e`): runs on pull requests and pushes (`main`, `release/*`, and `v*` tags) and gates `ci-gate` (and transitively `automerge`), `release-and-archive`, and `deploy-docs`, executing Playwright accessibility E2E suites for `subject-portal` and `web` (failing closed with exit code `1` if Playwright browser installation fails three times), plus `BrowserCorrectionReachesTheDatabaseWithItsReason` (`tests/Cadence.IntegrationTests`) against PostgreSQL 18 with `CADENCE_TEST_BROWSER=1`.
10. **GxP Compliance & Qualification Reporting** (`compliance`): downloads the verified `gxp-test-evidence-${{ github.run_id }}-${{ github.run_attempt }}` artifact (TRX reports and `*.database.txt` fixture evidence) from `dotnet-tests` into `TestResults/gxp`, then `Generate Compliance Reports` runs `node scripts/run-cli.js gxp sync --results-dir TestResults/gxp`, which writes a preview of the RTM and IQ/OQ/PQ report to `TestResults/gxp/preview/` without re-running `dotnet test` and fails on unknown requirement IDs, failing tagged tests, missing `*.database.txt` metadata and skipped database tests; it writes `docs/SDLC` only with `CADENCE_GXP_SNAPSHOT=1`. `Check GxP Snapshot Policy` runs `node scripts/run-cli.js check gxp-snapshot`, which fails when the branch changes the committed RTM, IQ/OQ/PQ report or `docs/SDLC/runs/` (ADR-2532). With `CADENCE_GXP_SNAPSHOT=1` it instead compares the regenerated documents with the snapshot (`cadence gxp diff`, which ignores the evidence block naming the tested revision, time, database and runner).
11. **CI Gate** (`ci-gate`): runs with `if: always()` and depends on all 11 pull-request validation jobs (`actionlint`, `lint-and-static`, `dotnet-quality`, `native-aot-build`, `docs-build`, `security`, `container-security`, `unit-tests`, `dotnet-tests`, `accessibility-e2e`, `compliance`). It fails whenever any required upstream job (`actionlint`, `lint-and-static`, `dotnet-quality`, `native-aot-build`, `docs-build`, `security`, `unit-tests`, `dotnet-tests`, `accessibility-e2e`, `compliance`) fails, cancels, or skips, and fails on `container-security` failure or cancellation while allowing `container-security` to skip on pull requests that touch no container or dependency inputs.
12. **Classify Change** (`classify`, pull requests) and **Enable Automerge** (`automerge`, pull requests): `classify` labels documentation-only pull requests (`is_safe=true`) and detects container/dependency changes (`container_scan=true`); `automerge` waits on `classify` (`is_safe == 'true'`) and `ci-gate` (`needs.ci-gate.result == 'success'`) before running `gh pr merge --auto --squash` with `GITHUB_TOKEN`.

### Branch rulesets and local reconciliation

`.github/rulesets/main.json` (`refs/heads/main`) and `.github/rulesets/release_branches.json` (`refs/heads/release/*`) enforce `strict_required_status_checks_policy: true` and require only two GitHub Actions (`integration_id: 15368`) checks: `CI Gate` (`ci.yml`) and `Check for Merge Conflicts` (`conflict-check.yml`), decoupling branch protection rules from internal CI job refactors. `.github/rulesets/version_tags.json` blocks deletion and force-pushes on `refs/tags/v*`. The `rulesets` quality gate (`pnpm cadence check rulesets`) verifies ruleset JSON schema, strict policy, `CI Gate` upstream job coverage, and workflow parity. While GitHub Actions runners stay paused until 2027, maintainers reconcile declarative rulesets locally with admin credentials using `pnpm cadence rulesets --dry-run` (preview) and `pnpm cadence rulesets` (`gh api` sync; fails non-zero on API or permission errors).

Jobs that run `node scripts/run-cli.js` across `ci.yml`, `production-pipeline.yml`, and `deploy-docs.yml` cache `./bin/cadence` via `actions/cache` (keyed on global MSBuild files, `packages/cli/src/**`, and all `Cadence.Cli` `ProjectReference` trees), and every active `actions/setup-dotnet` step hashes `global.json`, `Directory.Build.props`, `Directory.Packages.props`, and `**/*.csproj`. Only the release and documentation deployment callers run exclusively on pushes (where `cancel-in-progress` is disabled so release evidence runs complete): `release-and-archive` (`production-pipeline.yml`, on `main`, `release/*`, and `v*` tags, gated on all 11 validation jobs and forwarding `gxp-test-evidence-${{ github.run_id }}-${{ github.run_attempt }}` into `gxp snapshot --results-dir TestResults/gxp` to publish `gxp-release-evidence-${{ github.sha }}-${{ github.run_id }}-${{ github.run_attempt }}`) and `deploy-docs` (`deploy-docs.yml`, on `main`, gated on all 11 validation jobs independently of `release-and-archive` so documentation publishing and release archiving run in parallel). While GitHub Actions is paused, verify container changes locally with Hadolint (`find docker -type f -name "Dockerfile*" -exec hadolint --failure-threshold error {} +`), container builds (`docker build -t cadence-gateway:latest -f docker/Dockerfile.dotnet --build-arg APP_NAME=gateway .`, `docker build -t cadence-kernel-api:latest -f docker/Dockerfile.dotnet --build-arg APP_NAME=kernel-api .`, `docker build -t cadence-sce-python:latest -f docker/sce/python/Dockerfile docker/sce/python`, `docker build -t cadence-sce-r:latest -f docker/sce/r/Dockerfile docker/sce/r`), and Trivy (`trivy image --exit-code 1 --ignore-unfixed --pkg-types os,library --severity CRITICAL,HIGH cadence-gateway:latest`).

> [!IMPORTANT]
> GitHub Actions does not run jobs for this repository until 2027: every check on a pull request fails within seconds
> without running. Until then, run `pnpm cadence ci` (or `make ci`) before merging. It runs the pull-request jobs above
> (starting with `actionlint`) on your machine with the same commands, requires `actionlint`, `hadolint`, `shellcheck`,
> `detect-secrets-hook` and `bash` on `PATH` plus PostgreSQL for the .NET tests, and fails when any required binary or
> database is missing unless `--allow-skip` is passed ([cli.md](cli.md#cadence-ci)). A full run takes about 20 minutes:
> `CADENCE_TEST_POSTGRES=<connection string> pnpm cadence ci`. Without a terminal (an AI agent, a script, a pipe, a git
> hook) the CLI prints plain text, so its output can be redirected to a file as it is.

## Quality gates

`pnpm cadence check` runs every gate in `packages/cli/src/Services/QualityGates.cs`, the one registry of quality gates. The pre-commit hook runs a quicker variant (below), and CI partitions the registry across existing runtime jobs with `--exclude` (`api-clients` runs in `lint-and-static`, `vulnerabilities` runs in `security`, and `dotnet-quality` runs `check --exclude api-clients --exclude vulnerabilities`). Run one gate with `pnpm cadence check <gate>`; an unknown gate name (or unknown `--exclude` gate) fails. While GitHub Actions remains disabled until 2027, contributors running pre-commit hooks, `pnpm cadence check` or `pnpm cadence ci` locally must restore `Cadence.sln` (`dotnet restore Cadence.sln`) and provision `pip-audit` in a virtual environment (`python3 -m venv .venv && .venv/bin/python -m pip install --upgrade pip pip-audit==2.10.1` or on `PATH`), because the `vulnerabilities` gate fails closed whenever `.NET`, `pnpm` or `pip-audit` scanners are missing, unrestored or return errors. The table is generated from the registry by `pnpm cadence generate-cli-docs`, and the `cli-docs` gate fails when it is stale. [cli.md](cli.md#cadence-check) lists each gate's other names and what the pre-commit hook does with it. `QualityGateRegistryTests` runs every gate against a fixture that must make it fail, so a gate that cannot fail does not get in.

`pnpm cadence check rtm` (or `gxp-rtm-validate`) validates the requirement tags and integrity stamps without regenerating the matrix; it requires the matrix's test mapping to be current only with `CADENCE_GXP_SNAPSHOT=1`. `pnpm cadence check gxp-snapshot` (or `gxp-snapshot-guard`) runs the snapshot guard. `pnpm cadence check baseline-ratchet` (or `baselines`) runs the baseline ratchet ([docs/TESTING.md](TESTING.md#ratchet-baselines)); it runs inside `pnpm cadence check`, so CI's `Run Cadence quality sentinels` step and `cadence ci` run it too.

## Pre-commit hook

`scripts/setup_wizard.sh` points git at `.githooks/` (`git config core.hooksPath .githooks`). The `pre-commit` hook (`pre-commit.ps1` on Windows) runs:

1. `dotnet format Cadence.sln --verify-no-changes --include <staged .cs files>`, skipped when no C# file is staged.
2. `pnpm cadence check --pre-commit`: every gate, limited to the staged files where a gate takes files, with the shortcuts listed in [cli.md](cli.md#cadence-check): the two format gates are skipped (step 1 covers the staged C# files), the `schema-doc` gate runs the drift check when staged files include Entity Framework entities, migrations, or configurations, the `openapi` gate exports specs only for the services the staged C# files touch, and the `gxp-snapshot` and `baseline-ratchet` gates check the staged copies; `baseline-ratchet` admits staged growth when `CADENCE_BASELINE_GROWTH="<reason>"` is set, and the commit then needs a `Baseline-Growth: <reason>` trailer. `pnpm cadence check`, `make verify` and CI run every gate in full.

Additionally, `.pre-commit-config.yaml` configures `rhysd/actionlint` and local `workflow-security` (`node scripts/run-cli.js check workflow-security`) hooks to ensure all GitHub Actions workflows and composite actions are syntax-checked, pinned to 40-character commit SHAs or `sha256:` container digests, and scoped to least-privilege permissions.

There is no pre-push hook. Requirement tags and test results are checked in CI by the compliance job; run `pnpm cadence gxp sync` before pushing test changes, and commit nothing it generates.

```bash
# Run the same checks without committing
dotnet format Cadence.sln --verify-no-changes
pnpm cadence check

# Enable the hooks by hand if setup was skipped
git config core.hooksPath .githooks
```

Don't bypass the hook with `--no-verify`; fix the failing gate instead.

## CI failure runbook

CI runs in `.github/workflows/ci.yml`. `pnpm cadence ci` reproduces the whole workflow; each check can also be reproduced on its own with the command in the last column.

| Failing job or step                                    | Usual cause                                                                                       | Reproduce and fix locally                                                                                                                                                                                                                                                                                                                                     |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Workflow Action Pinning & Actionlint Gate              | Action not pinned, persisted checkout creds, unscoped permissions, or actionlint YAML error       | `pnpm cadence check workflow-security`, `actionlint`, `pnpm cadence ci --job actionlint`, or `pre-commit run actionlint --all-files`                                                                                                                                                                                                                          |
| Lint and Static › Build frontend workspace             | Vite or Rollup build failure in `packages/ui`, `apps/web` or `apps/subject-portal`                | `pnpm build`                                                                                                                                                                                                                                                                                                                                                  |
| Lint and Static › Run frontend style and lint          | ESLint or Prettier findings in `apps/web`, `apps/subject-portal` or `packages/ui`                 | `pnpm format` and `pnpm -r lint`                                                                                                                                                                                                                                                                                                                              |
| Lint and Static › Validate web API clients             | Stale generated OpenAPI TypeScript types or web client type error                                 | `pnpm --filter web run generate:api` and `pnpm cadence check api-clients`                                                                                                                                                                                                                                                                                     |
| Lint and Static › Run Hadolint or ShellCheck           | Dockerfile or shell script findings                                                               | `find docker -type f -name "Dockerfile*" -exec hadolint --failure-threshold error {} +`, `shellcheck <script>`                                                                                                                                                                                                                                                |
| Lint and Static › Run installer checksum tests         | SHA-256 verification regression in `setup_dotnet_env.sh` or `setup_dotnet_wizard.sh`              | `bash tests/test_installer_checksums.sh`                                                                                                                                                                                                                                                                                                                      |
| .NET Quality › Run Cadence quality sentinels           | A quality gate (`dotnet-format`, `workflow-security`, `rulesets`, `openapi`, `adrs`, etc.) failed | `pnpm cadence check <gate>` (for formatting: `dotnet format Cadence.sln`, for workflow security: `pnpm cadence check workflow-security`, for rulesets: `pnpm cadence check rulesets` and `pnpm cadence rulesets --dry-run`, for OpenAPI: `pnpm cadence sync-openapi-spec && pnpm cadence generate-api-docs`, for ADRs: `pnpm cadence scaffold adr "<title>"`) |

| Security › Run dependency audit                        | A vulnerable NuGet, pnpm or Python package, an un-restored `Cadence.sln`, or missing `pip-audit`  | Run `dotnet restore Cadence.sln` and `python3 -m venv .venv && .venv/bin/python -m pip install --upgrade pip pip-audit==2.10.1`, then `pnpm cadence check vulnerabilities`; upgrade in `Directory.Packages.props`, `package.json` or `pnpm-workspace.yaml`                                                                                                    |
