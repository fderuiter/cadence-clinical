# Architectural Decision Records (ADRs) Index

This document is the static hub for Architectural Decision Records across the Cadence Clinical platform. Active decisions are sharded into eight domain directories (`docs/adr/<domain>/index.md`), while legacy sequential `ADR-NNNN` decisions remain frozen in [`legacy-index.md`](legacy-index.md).

## Standard ADR Template & Scaffolding

- [ADR Template](TEMPLATE.md)
- Scaffold a new ADR with `pnpm cadence scaffold adr --domain <domain> "<title>"` (or `dotnet run --project packages/cli/src/Cadence.Cli.csproj -- scaffold adr --domain <domain> "<title>"`).
- Allowed `--domain` slugs: `kernel`, `platform`, `security`, `standards`, `operations`, `compliance`, `frontend`, `tooling`.
- Scaffolding writes `docs/adr/<domain>/YYYY-MM-DD-<slug>.md` headed `# ADR-<DOMAIN>-YYYYMMDD-<slug>: <title>` and inserts its link in alphabetical filename order into `docs/adr/<domain>/index.md` without modifying `docs/adr/index.md`.
- Validate with `pnpm cadence check adrs`.

## Numbering Rules {#numbering-rules}

New ADRs use collision-free domain-slug identifiers on line 1 (`# ADR-<DOMAIN>-YYYYMMDD-<slug>: <title>`) inside `docs/adr/<domain>/YYYY-MM-DD-<slug>.md`, sorted alphabetically by filename in `docs/adr/<domain>/index.md` so parallel pull requests merge cleanly without sequential number reservations.

Historical `ADR-NNNN` records (`ADR-049` through `ADR-2899`) remain at their original `docs/adr/YYYY-MM-DD-*.md` paths and are indexed in [`legacy-index.md`](legacy-index.md). `pnpm cadence check adrs` enforces unique identifiers across both legacy and domain ADRs, alphabetical sorting within every shard, full index coverage, and valid relative links.
