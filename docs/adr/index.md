# Architectural Decision Records (ADRs) Index

This document tracks all Architectural Decision Records for the Cadence Clinical platform categorized by functional domain.

## Standard ADR Template & Scaffolding

- [ADR Template](TEMPLATE.md)
- Scaffold a new ADR with `pnpm adr:new "<title>"` or `dotnet run --project packages/cli/src/Cadence.Cli.csproj -- scaffold adr "<title>"`. It writes `docs/adr/YYYY-MM-DD-<slug>.md` headed `# ADR-<highest number + 1>: <title>` and appends an entry to the end of this index; renumber it into its area's block (see the numbering rules below) and move that entry into the matching domain section.
- Validate with `dotnet run --project packages/cli/src/Cadence.Cli.csproj -- check adrs`.

## Numbering Rules

Every ADR has exactly one unique number, given on its first line as `# ADR-NNNN: Title` (numbers below 1000 keep their historical three-digit form, such as `ADR-049`). When a number was found to be shared by several files, the oldest file kept it and the later files were renumbered in date order; a renumbered ADR carries an `Also known as: ADR-XXX (former number)` line directly under its heading so older references still resolve. `check adrs` fails on duplicate numbers, a missing `# ADR-` heading, an ADR missing from this index or listed twice, and any link in this index that does not resolve.

Reservation rule: since the kernel work of September 2026, a new ADR takes the next free number in the block reserved for its area, not the next number after the highest one. The highest numbers belong to the Stitch block, so the scaffolder's default (one more than the highest) is wrong for every other area: renumber the heading after scaffolding (#5439 tracks fixing the scaffolder). Parallel pull requests may claim numbers at the same time, so re-check `main` before pushing and renumber your ADR if its number has been taken. Numbers claimed by open pull requests stay free here until those ADRs merge, so gaps in the sequence are expected.
