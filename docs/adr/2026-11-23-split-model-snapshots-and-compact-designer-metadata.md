# ADR-2824: Split EF Core Model Snapshots Per Entity, Compact Designer Metadata, and Enforce Full DDL Constraint Uniqueness

- **Status:** Accepted
- **Date:** 2026-11-23
- **Authors:** @fderuiter
- **Deciders:** @fderuiter
- **Requirements:** PRD-SYS-053 (development guardrails and deterministic GxP verification evidence), PRD-EVT-001

---

## 1. Context & Problem Statement

[ADR-2536](2026-11-22-unify-18-module-migrations-and-strip-schema-doc-counts.md) unified EF Core migration tooling across all 18 persistence modules (`PersistenceModuleCatalog.All`), retired tracked `idempotent_migration.sql` dumps, and stripped volatile table/column counts from `docs/schema`. Four migration contention, duplication, and verification gaps remained:

1. **Monolithic `*ModelSnapshot.cs` Merge Contention:** All 18 persistence modules serialized every entity table block, foreign-key/owned block, and navigation block into a single `BuildModel(ModelBuilder)` method (`23,137` lines across 18 `*ModelSnapshot.cs` files, including `5,105` lines and 63 root entities in `KernelDbContextModelSnapshot.cs`). Parallel branches adding adjacent entities or navigations in the same module conflicted in `git merge-file`.
2. **Duplicated `*.Designer.cs` Target Models:** All `155` `*.Designer.cs` files duplicated full point-in-time `BuildTargetModel(ModelBuilder)` snapshots (`239,533` compiled C# lines), slowing C# compilation and drifting silently during parallel branch merges (for example, `20261006192109_ProposalConfidenceAndEscalation.Designer.cs` omitting `FormVersionSnapshot` after a merge).
3. **Secret-Scanning Blind Spot:** `SecretsBaselineCleanerService.CanonicalExcludePattern` exempted `Migrations/[^/]+\.Designer\.cs$`, leaving `155` compiled source files outside `detect-secrets` coverage.
4. **Incomplete Offline Constraint Verification:** `SchemaMigrationValidator` checked `CreateTableOperation` and `AddColumnOperation` uniqueness but did not inspect unsplit `*ModelSnapshot.cs` files, orphan snapshot partials, uncompacted `*.Designer.cs` bodies, or duplicate index, foreign-key, unique, and check constraints. In addition, `MigrationToolingService` did not pass `--context <DbContextName>` to `dotnet ef`, causing `cadence migrations script` to fail on `executionmodule` (`Cadence.Modules.Execution` hosts both `ExecutionModuleDbContext` and `ExecutionSignatureTokenDbContext`).

This ADR supersedes the deferred snapshot-splitting clause (§2) and the `BuildTargetModel` requirement (§4.4) in [ADR-2536](2026-11-22-unify-18-module-migrations-and-strip-schema-doc-counts.md) while keeping squashing of historical migrations and custom `.gitattributes` merge drivers out of scope.

## 2. Decision Drivers & Constraints

- Preserve runtime migration execution, migration IDs, `Up`/`Down` operations in `Cadence.DatabaseMigrator`, and byte-for-byte idempotent SQL output from `cadence migrations script all` across all 18 modules.
- Keep `packages/cli/src/Cadence.Cli.csproj` 100% compatible with `PublishAot=true` (zero `IL2xxx`/`IL3xxx` warnings) and preserve `K-XS-2` assembly boundary rules in `KernelBoundaryRules.cs` with zero new cross-assembly references.
- Emit `// <auto-generated />` headers and LF (`\n`) line endings on all generated files under `Migrations/` to satisfy `CS1591` (including `Cadence.Modules.Execution`), Sonar analyzers, and `CodeMetadataCatalog`.
- Allow baseline tables created via `SqlOperation` (such as `audit_log_entries` in standalone services) to receive later index or constraint migrations without false missing-table errors.

## 3. Options Considered

### Option 1: Per-entity `Migrations/Snapshots/*.Snapshot.cs` partials with three-pass ordinal discovery, attribute-only `*.Designer.cs` compaction, full secret-scan coverage, and full DDL constraint validation (Selected)

- **Overview:** Add `MigrationSnapshotCompactor` in `Cadence.ToolingCore` (invoked by `cadence migrations add` and `cadence fix`) to split each module's `*ModelSnapshot.cs` into a static root snapshot plus one `Migrations/Snapshots/<EntityFullName>.Snapshot.cs` partial per non-owned entity, compact all `*.Designer.cs` files to `[DbContext]` and `[Migration]` partial declarations without `BuildTargetModel`, decorate `IMigrationsSqlGenerator` on `KernelDbContext` so default-schema resolution on compacted `TargetModel` instances preserves byte-identical `EnsureSchema` SQL, remove `Migrations/[^/]+\.Designer\.cs$` from `SecretsBaselineCleanerService.CanonicalExcludePattern` and `baselines/secrets/config.json`, pass `--context <DbContextName>` in `MigrationToolingService`, and extend `SchemaMigrationValidator` to reject unsplit snapshots, orphan/missing snapshot partials, uncompacted `*.Designer.cs` files, and duplicate index, foreign-key, unique, and check constraints.
- **Pros:**
  - Static root `*ModelSnapshot.cs` discovers nested `IEntitySnapshot` types at design/test model-build time and runs `ConfigureTable`, `ConfigureForeignKeys`, and `ConfigureNavigations` in `StringComparer.Ordinal` order by `EntityName`, so parallel branches adding distinct entities or navigations pass `git merge-file` with exit code `0`.
  - Eliminates `237,363` lines (`99.09%`) across `155` `*.Designer.cs` files (`239,533` lines down to `2,170` lines) and removes the `*.Designer.cs` secret-scan exemption.
  - Pure C# source parsing in `Cadence.ToolingCore` keeps `Cadence.Cli` 100% Native AOT-compatible and respects `K-XS-2`.
- **Cons:**
  - `dotnet ef migrations remove` cannot reconstruct a prior snapshot from the penultimate `*.Designer.cs` `BuildTargetModel`; reverting an unmerged migration uses `git checkout` / `git rm` on the branch's migration and snapshot partial files instead.

### Option 2: Keep monolithic `*ModelSnapshot.cs` and `BuildTargetModel` bodies and rely on manual conflict resolution

- **Cons:**
  - Leaves parallel feature branches conflicting on adjacent `modelBuilder.Entity(...)` blocks, retains >237,000 lines of duplicated generated C#, and keeps `*.Designer.cs` excluded from `detect-secrets`.

## 4. Decision Outcome

**Chosen option: Option 1.**

1. Added `MigrationSnapshotCompactor` (`packages/tooling_core/src/Services/MigrationSnapshotCompactor.cs`) and wired it into `MigrationToolingService.Add` and `SelfHealService.ExecuteSelfHealing` (`pnpm cadence fix`), splitting all 18 `*ModelSnapshot.cs` files into static root snapshots plus `271` per-entity partial files under `Migrations/Snapshots/*.Snapshot.cs`.
2. Each static root `*ModelSnapshot.cs` defines a private `IEntitySnapshot` interface (`EntityName`, `ConfigureTable`, `ConfigureForeignKeys`, `ConfigureNavigations`), discovers nested implementations via `GetNestedTypes(BindingFlags.NonPublic)`, sorts by `EntityName` with `StringComparer.Ordinal`, and executes table, foreign-key/owned, and navigation passes in strict ordinal order.
3. Compacted all `155` `*.Designer.cs` files across the 18 persistence modules to `[DbContext]` and `[Migration]` partial declarations without `BuildTargetModel` bodies (`239,533` lines reduced to `2,170` lines), and added `KernelDefaultSchemaMigrationsSqlGenerator` in `KernelQueryTranslationOptionsExtension` so `AlterDatabaseOperation` extension migrations preserve `KernelDbContext.Schema` and byte-identical idempotent SQL output across all 18 modules.
4. Passed `--context <DbContextName>` in `MigrationToolingService.Add`, `Script`, and `List` so multi-context assemblies such as `Cadence.Modules.Execution` resolve unambiguously.
5. Removed `Migrations/[^/]+\.Designer\.cs$` from `SecretsBaselineCleanerService.CanonicalExcludePattern` and `baselines/secrets/config.json` so `detect-secrets` scans every file under `Migrations/`.
6. Extended `SchemaMigrationValidator` (`packages/tooling_core/src/Cadence.SchemaDocExporter/SchemaMigrationValidator.cs`) to fail closed on unsplit `*ModelSnapshot.cs` files, missing or orphan `Migrations/Snapshots/*.Snapshot.cs` partials, uncompacted `*.Designer.cs` `BuildTargetModel` bodies, and duplicate active indexes, foreign keys, unique constraints, and check constraints (while lazily tracking `SqlOperation`-created baseline tables).

## 5. Consequences & Trade-offs

- Parallel branches adding distinct entities in the same module create independent `Migrations/Snapshots/<Entity>.Snapshot.cs` files without touching the root `*ModelSnapshot.cs`, merging cleanly via standard `git merge-file`.
- Direct invocations of `dotnet ef migrations add` are caught offline by `pnpm cadence check schema-doc` and `pnpm cadence migrations verify` and normalized automatically by `pnpm cadence fix`.
- Every `.cs` file under `Migrations/` and `Migrations/Snapshots/` is scanned by `pnpm cadence check detect-secrets`.
