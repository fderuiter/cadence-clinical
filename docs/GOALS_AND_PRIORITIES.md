# Goals and priorities

The active objectives for Cadence Clinical. Each goal has a code-level outcome and a way to verify progress. See the [project plan](PROJECT_PLAN.md) for module ownership, delivery dependencies, and engineering practices.

## Now

| Goal                                        | What success looks like                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Reproducible release evidence**           | Mandatory PostgreSQL test groups execute against the named revision and environment. Failed, skipped, and unexecuted results are visible and leave the requirement unqualified. [#5695](https://github.com/fderuiter/cadence-clinical/issues/5695) · [#5696](https://github.com/fderuiter/cadence-clinical/issues/5696)                                                                                                                         |
| **Fast, reliable coordinator visit**        | One synthetic visit passes from entry to signed lock through the real stack. Measure verified workflow steps and p95 input feedback and committed-save latency on a fixed profile. [#5365](https://github.com/fderuiter/cadence-clinical/issues/5365) · [#5369](https://github.com/fderuiter/cadence-clinical/issues/5369)                                                                                                                      |
| **Explainable edits and queries**           | A versioned edit check raises one query linked to the exact value revision. Teams can act in context, and retry and lock-race tests show a consistent result. [#5368](https://github.com/fderuiter/cadence-clinical/issues/5368) · [#5586](https://github.com/fderuiter/cadence-clinical/issues/5586)                                                                                                                                           |
| **Integrity and recoverability**            | Tests exercise access scope, version-bound signatures, audit integrity, atomic writes, concurrent locks, and job restart or replay. Track covered named invariants and require each applicable positive and negative case to pass. [#5364](https://github.com/fderuiter/cadence-clinical/issues/5364) · [#5367](https://github.com/fderuiter/cadence-clinical/issues/5367) · [#5470](https://github.com/fderuiter/cadence-clinical/issues/5470) |
| **Maintainable modules and trustworthy CI** | Reduce existing forbidden dependencies under the same architecture rules, keep typed API clients in sync, and close concrete CI hardening gaps with executed checks. Track removed violations, verified contracts, and required checks that completed. [#5367](https://github.com/fderuiter/cadence-clinical/issues/5367) · [#5704](https://github.com/fderuiter/cadence-clinical/issues/5704)                                                  |
