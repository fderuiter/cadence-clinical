# Execution module

Execution's eCRF forms as a module of the kernel composition host ([ADR-2601](../../../docs/adr/2026-10-19-one-composition-host-for-the-kernel-and-its-modules.md), [ADR-2622](../../../docs/adr/2026-10-19-ecrf-forms-are-collection-instances-saved-in-one-command.md), #5460). The kernel holds a form's clinical truth: the `CollectionInstance`, its values as observations, the assertions, signatures and locks. This module adds what only Execution needs, the form's layout and the data query workflow (#5461), and serves the eCRF screen's routes. The rest of Execution (subjects, consent, CEC, toxicity) still runs as the standalone [Execution service](../README.md) until it moves here too.

**Status:** forms open, read, save and are signed, and queries (on recorded values or blank items) are raised, listed per enrollment or across a study's visible enrollments, answered, reopened, closed and cancelled, end to end on PostgreSQL through the kernel host, alongside kernel observation SDV (#5465). Edit checks (#5368) and lock management (#5466) over the HTTP surface come next.

## Project

- Project: `apps/execution/module/Cadence.Modules.Execution.csproj`. Of the kernel it references only `Cadence.Kernel.Abstractions` and the module SDK `Cadence.Kernel.Modules` (K-XS-2), plus `Cadence.Core.Domain` and `Cadence.Security`; the kernel host references it.
- `ExecutionModule.AddCadenceExecutionModule(connectionString)` registers the module with the kernel's authorization (`AddCadenceModule`), its command store in the `execution` schema, the `OpenFormInstance`, query, and SDV alert command handlers and validators, and the event consumers. `MapExecutionModule()` maps the routes, each for a signed-in caller whose access the kernel then decides per object.
- `Domain/FormInstance`: one per kernel form instance, with the same id. It snapshots the CollectionSpec's item order from the governing protocol version when the form opens, so the screen keeps its layout.
- `Application/OpenFormOnCollectionOpened`: consumes the kernel's `CollectionInstanceOpened` event after commit and sends `OpenFormInstance` (`execution.form.open`) as `svc:execution-forms`, keyed by the delivery, so a redelivered event changes nothing twice. A kernel form the module cannot find, or that names another enrollment, is `M.Execution.Form.CollectionInstanceUnknown`.
- `Domain/FormSdvAlert`, `Application/AlertMonitorOnVerifiedObservationCorrected`, and `Endpoints/ExecutionStudySdvAlertReader`: insert-only CRA source-data-verification modification alerts (`execution.form_sdv_alerts`, `KA001`, `PRD-QRY-006`). When `ObservationCorrected` fires, `AlertMonitorOnVerifiedObservationCorrected` reads the observation through `IObservationRecords` (K-XS-2) and, if the superseded revision held an active `Verified` assertion at the moment it was superseded, sends idempotent `RecordFormSdvAlert` (`execution.query.manage`) as `svc:execution-sdv-alerts` keyed by the outbox delivery, storing kernel `StudyId`, `StudySiteId`, `EnrollmentId`, `CollectionInstanceId`, and `ObservationId` (K-MOD-1). Active alerts collapse per observation in SQL (`SELECT DISTINCT ON (observation_id)`), pre-filter re-verified revisions and classify blinding through `IObservationRecords.FindUnverifiedSdvTargetsAsync`, and flow into the kernel's Wave-1 `GET /api/v1/kernel/studies/{studyRef}/attention` payload through the narrow `IStudySdvAlertReader` port.
- `Domain/FormQuery`: a bitemporal data query aggregate (`AggregateRoot<FormQueryId>`, [ADR-2625](../../../docs/adr/2026-11-22-bitemporal-form-query-aggregate-and-provenance.md), `PRD-QRY-001`, `PRD-QRY-002`) about one revision of one value, targeting the kernel `(ObservationId, Revision)` (spec §11: the query workflow is EDC's). Tracks status (`open`, `answered`, `closed` or `cancelled`), `origin` (`manual` or `system`), `owner_role` (`site`, `monitor` or `data_manager`), optional `assignee`, `priority` (`low`, `normal` or `high`), `opened_at`, `status_since`, 14-day `due_at` while open, `escalated_at`, `last_answered_by`, bitemporal state intervals (`execution.form_query_periods`, `KT001` + `ex_form_query_periods_bitemporal`), and insert-only `messages` (`execution.form_query_messages`, `KA001`) carrying both conversational text and verbatim `reason_for_change`. Raising refuses anything but the value's current revision (`M.Execution.Query.RevisionStale`) and a value of another form (`M.Execution.Query.ObservationUnknown`); closing an `open` manual query is refused (`M.Execution.Query.InvalidTransition`), and closing an `answered` manual query by `LastAnsweredBy` is refused with 409 `M.Execution.Query.SeparationOfDuties`. Every query command links `form_query:{id}` to its governing `Enrollment` and `Observation` in kernel lineage, shares the form's lock scopes first (ADR-2621), and is refused with 423 `K.Assertion.Locked` while a Locked lock covers the value; a Frozen lock stops data entry, not queries.
- `Application/EvaluateEditChecksOnCollectionChanged`, `Application/FormQueryEscalationService`, `Application/FormQueryEscalationHostedService`, and `Application/SendFormQueryAgingDigestAlerts`: post-commit outbox validation opens and closes deterministic `system` queries (`ADR-2624`) and automatically answers `open` `manual` queries (`AutoAnswerFormQuery`) when `RecordCollectedValues` or `CorrectObservation` advances the queried observation's revision, preserving the human editor and verbatim `ReasonForChange` while clearing any stale site assignee. `FormQueryEscalationHostedService` runs a leader-locked daily pass (`execution.query-sla-sweep`) across active, Capture-entitled tenants and studies as `svc:execution-query-sla`, evaluating open queries past their 14-day `DueAt` via `IClock`, dispatching `EscalateFormQuery` (`Priority = High`, `EscalatedAt = now`), and persisting PII-free daily aging digests (`execution.form_query_aging_digests`, `KA001`) for `study_lead` and `site_investigator`. Saving a digest emits `execution.FormQueryAgingDigestGenerated`, consumed idempotently by `SendFormQueryAgingDigestAlerts` to notify de-identified site and study leads with blinded treatment items redacted.
- `Application/MirrorFormQueryToKernel`: each query step raises `execution.FormQueryChanged` with the target `Revision`, human `ActorId`, verbatim `ReasonForChange`, and kernel assertion commands it stands for, and this consumer sends them as `svc:execution-queries`, keyed by the delivery: raising states a kernel `Queried` assertion at the exact queried revision, answering a `QueryAnswered` at the current revision, closing or cancelling retracts the kernel query, reopening an answered query retracts the answer, and reopening a closed one raises a new kernel query (spec §8.2), preserving the human actor (`AssertedBy`) and verbatim `ReasonForChange`. The query chooses the assertion ids, so a redelivered event writes nothing twice; other applications count open queries from the kernel. A step refused because a Locked lock now covers the value is retried until the lock is released (#5586).
- `Endpoints/FormSignatureEndpoints`: the signing route. It verifies and spends the caller's step-up token, sends the kernel's `SignCollectionInstance` to record an `Attestation` over the form's content hash (ADR-2622 §4.5, #5463), and masks blinded signed values, hashes, and reasons in the immediate `201` response unless the caller holds `enrollment.unblind`.
- `Infrastructure/ExecutionSignatureTokenDbContext`: the durable single-use store for spent step-up tokens (`AddCadenceDurableSigTokenStore`), table `execution.consumed_signature_tokens`, shared by every host instance so a token is spent once across them. It has no tenant column and no Row-Level Security: a token id is a random `jti`, and the store keeps nothing clinical.
- `Infrastructure/ExecutionModuleDbContext`: tables `execution.form_instances`, `execution.form_queries`, `execution.form_query_periods`, `execution.form_query_messages`, `execution.form_query_aging_digests`, and `execution.form_sdv_alerts` with forced Row-Level Security on `tenant_id` (`ModuleTenantIsolationSql`), bitemporal triggers/GiST exclusion (`ModuleBitemporalSql`), and insert-only triggers (`ModuleInsertOnlySql`), plus the signature token table. `AddModuleMigrations` registers its migrations, which the host's `KernelMigrationHostedService` applies after the kernel's, and `ExecutionModuleDatabase.GrantAppRoleSql(role)` grants read, insert and update on mutable/period tables, read and insert only on insert-only message, digest, and SDV alert tables, and delete on the signature token table only, so expired tokens can be pruned. Reads outside commands use `AddModuleTenantContext` (a no-tracking context scoped to the caller's tenant).

## HTTP surface

Every route needs the gateway-signed caller, runs in the caller's kernel tenant (`KernelTenantFilter`) and answers RFC 9457 problem details with the kernel's stable error codes. Writes are kernel commands: they need an `Idempotency-Key` header, take the reason for change only from the signed identity, and are authorized against the form's enrollment. The wire is snake_case and values are typed (ADR-2623).

| Route (`/api/v1/execution/forms…`)                     | Does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET ?enrollment_id=`                                  | Lists summaries of the forms opened for an enrollment, oldest first, with completeness, recorded and missing-required counts, open and answered query counts, SDV verified and unverified counts, active locks and freezes, and current or superseded signature status. 400 without `enrollment_id`; 403 when the caller may not see the enrollment.                                                                                                                                                                                                                                 |
| `POST` (no suffix)                                     | Opens a form (`OpenCollectionInstance`, `collection.open`) for an enrollment, CollectionSpec, optional visit and collection time, under the protocol version in force. 201; 409 `K.Observation.ParticipantWithdrawn` once the participant is withdrawn.                                                                                                                                                                                                                                                                                                                              |
| `GET /{formId}`                                        | The form: items in layout order with their values and revisions, `complete` and `missing_required` (every required item needs a value; a reasoned missing value counts, while an unasked `NotAsked` placeholder remains missing), locks, assertions, `content_hash` and signatures, each `superseded` once a correction changed the form, with the values it signed. 403 when the caller may not see its enrollment.                                                                                                                                                                 |
| `PUT /{formId}/values`                                 | Saves a page (`RecordCollectedValues`, `collection.record`): each value names the revision it was edited from. 409 `K.Collection.RevisionStale` refuses the whole page; 422 `K.Collection.ValuesInvalid` names each bad item; 423 when locked; 409 `K.Observation.ParticipantWithdrawn` for a new value once the participant is withdrawn (corrections go on).                                                                                                                                                                                                                       |
| `POST /{formId}/signatures`                            | Signs the form (`SignCollectionInstance`, `collection.sign`) with `meaning` (`approved` or `responsibility`) and the `content_hash` the signer read. Needs `X-Sig-Token`: a fresh single-use gateway step-up token for action `/api/v1/execution/forms/{formId}/signatures` and semantic action `execution.form.sign`; 401 `REAUTHENTICATION_REQUIRED` otherwise. Allowed while `Frozen` (closeout signing) and refused with 423 `K.Assertion.Locked` while covered by `Locked`; 409 `K.Trust.TargetContentChanged` when the form changed since it was read. 201 with the signature. |
| `GET /{formId}/queries`                                | The form's queries, oldest first, each with `current_revision`, `value_changed`, `origin`, `owner_role`, `priority`, `due_at`, `escalated_at`, `last_answered_by`, and optional bitemporal `as_of` / `valid_at` / `known_at` inspection. 403 when the caller may not see the enrollment.                                                                                                                                                                                                                                                                                             |
| `GET /queries?enrollment_id=`                          | The queries on every form of an enrollment (with optional `as_of` / `valid_at` / `known_at`), for the participant record. 403 when the caller may not see the enrollment.                                                                                                                                                                                                                                                                                                                                                                                                            |
| `GET /queries?study_id=`                               | Study-wide query worklist across enrollments the caller may see (`IKernelReadAccess.CanSeeAsync`) under tenant RLS, enriched with `site_code`, `subject_code`, `collection_spec_id` and `planned_activity_id`, and filterable by `status`, `owner`, `origin`, `priority`, `escalated`, `assignee`, `site`, `participant`, `value_changed`, and `as_of` / `valid_at` / `known_at`. 403 when the caller may not see the study; 404 when unknown.                                                                                                                                       |
| `GET /queries/digests?study_id=`                       | Daily PII-free aging escalation digests (`execution.query.read`), scoping study-wide digests (`study_lead`) to callers with study-wide grant coverage (`CoversScopeAsync`) and site digests (`site_investigator`) to visible sites, while redacting blinded entries unless the caller holds `enrollment.unblind`.                                                                                                                                                                                                                                                                    |
| `POST /queries/escalate?study_id=`                     | Evaluates overdue open queries (`now >= due_at`) across the study (`execution.query.manage`, active `ProductFamily.Capture` entitlement, mandatory `Idempotency-Key` and verbatim `X-Change-Reason`), escalating them to `high` priority and recording daily aging digests (`execution.FormQueryAgingDigestGenerated`).                                                                                                                                                                                                                                                              |
| `GET /sdv-alerts?study_id=&study_code=&enrollment_id=` | Active CRA SDV modification alerts (`PRD-QRY-006`) across visible enrollments in a study (`study_id` or `study_code` resolved through `IStudyDirectory`) or a single enrollment, collapsing episodes per observation with latest unverified revision attribution, omitting observations once monitors verify the latest revision, and suppressing blinded randomization items unless the caller holds `enrollment.unblind`.                                                                                                                                                          |
| `POST /{formId}/queries`                               | Raises a query (`RaiseFormQuery`, `execution.query.raise`) on `observation_id` at its current `revision`, or on a blank `item_id` (first materializing `MissingValue(NullFlavor.NotAsked)` at revision 1 via `RecordUnaskedCollectionItem`, `collection.record_unasked`), with `text` and optional `owner_role`, `priority`, and `assignee`. 201.                                                                                                                                                                                                                                    |
| `POST /{formId}/queries/{queryId}/answer`              | Answers an open query (`AnswerFormQuery`, `execution.query.answer`) with `text`, optional replacement `assignee` (otherwise clearing any stale assignee on `owner_role` handoff), and signed `X-Change-Reason`.                                                                                                                                                                                                                                                                                                                                                                      |
| `POST /{formId}/queries/{queryId}/reopen`              | Reopens an answered or closed query (`ReopenFormQuery`, `execution.query.manage`) with `text`, optional replacement `assignee` (otherwise clearing any stale assignee on `owner_role` handoff), and signed `X-Change-Reason`.                                                                                                                                                                                                                                                                                                                                                        |
| `POST /{formId}/queries/{queryId}/reassign`            | Reassigns or unassigns an open or answered query (`ReassignFormQuery`, `execution.query.manage`) with `assignee`, optional `owner_role` and `text`, `Idempotency-Key`, and signed `X-Change-Reason`, recording bitemporal (`FormQueryPeriod`) and message (`reassigned`) history.                                                                                                                                                                                                                                                                                                    |
| `POST /{formId}/queries/{queryId}/close`               | Closes an answered manual query or an open/answered system query (`CloseFormQuery`, `execution.query.manage`) with optional closing note `text` and signed `X-Change-Reason`; refuses open manual queries (`M.Execution.Query.InvalidTransition`) and self-closure by `last_answered_by` (`M.Execution.Query.SeparationOfDuties`).                                                                                                                                                                                                                                                   |
| `POST /{formId}/queries/{queryId}/cancel`              | Cancels an open or answered query raised in error (`CancelFormQuery`, `execution.query.manage`) with optional cancellation note `text` and signed `X-Change-Reason`.                                                                                                                                                                                                                                                                                                                                                                                                                 |

There are no batch routes: a client acting on several queries sends one command per query.

The gateway forwards `/api/v1/execution/forms/**` to the kernel host (`KERNEL_SERVICE_URL`); the two-segment prefix wins over Execution's `/api/v1/execution/**` by routing precedence.

## Authorization

The coordinator needs `collection.open`, `collection.record` and `execution.query.answer` at the participant's study site; the investigator needs `collection.sign` there (the demo user `pi.site101` has it); the monitor or data manager needs `execution.query.raise`, `execution.query.manage`, `collection.record_unasked` (to query blank items), `observation.verify` and `assertion.retract`. Without a grant every query command is denied (403 `K.Authorization.Denied`). Items bound to randomization or treatment-assignment concepts are masked in place (`NullFlavor.Masked` on values and revisions, redacted form hashes and signature payloads, masked pre-commit preview findings, and masked query text and messages) unless the caller holds `enrollment.unblind` on the enrollment, with multi-form and study-wide worklists batching unblinding checks (`IKernelReadAccess.CanUnblindManyAsync`), protocol designs (`IProtocolVersionReader.GetDesignsForStudyAsync`), and concept lookups (`IConceptRegistry.ResolveManyAsync`) once per distinct enrollment, version, and concept, and `EvaluateEditChecksOnCollectionChanged` suppresses automated queries on blinded items to prevent side-channel leaks (K-AUTH-4).

The consumers' and scheduler's service accounts need tenant-wide grants in every tenant that uses forms: `svc:execution-forms` needs `execution.form.open`, `svc:execution-queries` needs `observation.query`, `observation.query.answer` and `assertion.retract`, `svc:execution-query-sla` needs `execution.query.manage`, and `svc:execution-sdv-alerts` needs `execution.query.manage`. In Development the kernel host's demo data issues them (`DEMO_EXECUTION_FORMS`, `DEMO_EXECUTION_QUERIES`, `DEMO_EXECUTION_QUERY_SLA`, `DEMO_EXECUTION_SDV_ALERTS`); provisioning them in production is #5566.

## Tests

- `tests/Cadence.IntegrationTests/Execution/ExecutionFormModulePostgresTests.cs` (PostgreSQL, application role): opening a kernel form opens the module's form with the specification's item order, as `svc:execution-forms` with the delivery's idempotency key; a redelivered event opens one form; unknown, mismatched and existing forms are refused.
- `tests/Cadence.IntegrationTests/Execution/ExecutionFormHostPostgresTests.cs`: the real kernel host with a signed coordinator opens a form, saves pages, derives completeness and refuses a stale page whole; a caller without a grant can neither read nor save.
- `tests/Cadence.IntegrationTests/Execution/ExecutionFormQueryPostgresTests.cs` (PostgreSQL, application role): a query on a revision is stated as a kernel `Queried` assertion, answered and retracted on close, once however often the event is delivered; reopening withdraws the answer or raises a new kernel query; a cancelled query is final; a Locked lock refuses raising and answering, a Frozen one does not.
- `tests/Cadence.IntegrationTests/Execution/ExecutionFormQueryHostPostgresTests.cs`: through the kernel host, a monitor raises, the coordinator answers and corrects the value, the query shows the value changed and is closed; the coordinator can neither raise nor close and a stranger sees nothing (403).
- `tests/Cadence.IntegrationTests/Execution/ExecutionFormSignatureHostPostgresTests.cs`: through the kernel host, an investigator signs revision 1, a correction marks that signature superseded with the value it signed, a stale hash is refused (409), a second signature is current, and signing a form with blinded items masks blinded `signed_values`, `reason`, and `content_hash` in the immediate response while revealing them to unblinded callers; each signature writes an audit entry. A missing, expired, replayed or foreign step-up token is refused (401), a coordinator without `collection.sign` is denied (403) and an unknown meaning is refused (422).
- `tests/Cadence.UnitTests/Kernel/CollectionContentHashTests.cs`: the form content hash ignores read order and changes with every revision and value.
- `tests/Cadence.UnitTests/Execution/Module/ExecutionFormQueryTests.cs`: the steps each status allows and the kernel assertion each states.
- `tests/Cadence.UnitTests/Execution/Module/ExecutionFormProjectionDedupeTests.cs`: narrow `ICollectionInstanceRecords` fallbacks, summary query assertion id merging, bitemporal query pre-filtering and paging before target hydration, kernel blinding set reuse, batch study-enrollment escalation lookup, and deduplicated multi-form consumer reads.
- `tests/Cadence.IntegrationTests/Execution/ExecutionFormProjectionPerfPostgresTests.cs`: PostgreSQL 18 parity, Row-Level Security, blinding, lineage, Part 11 `ContentHash`, and SQL/memory bounds for narrow projections, 30-form enrollment listing, 300-form bitemporal query paging, multi-site SLA escalation sweeps, multi-form edit-check hydration, and deduplicated form/query mutations.
