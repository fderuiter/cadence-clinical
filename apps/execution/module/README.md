# Execution module

Execution's eCRF forms as a module of the kernel composition host ([ADR-2601](../../../docs/adr/2026-10-19-one-composition-host-for-the-kernel-and-its-modules.md), [ADR-2622](../../../docs/adr/2026-10-19-ecrf-forms-are-collection-instances-saved-in-one-command.md), #5460). The kernel holds a form's clinical truth: the `CollectionInstance`, its values as observations, the assertions, signatures and locks. This module adds what only Execution needs, the form's layout and the data query workflow (#5461), and serves the eCRF screen's routes. The rest of Execution (subjects, consent, CEC, toxicity) still runs as the standalone [Execution service](../README.md) until it moves here too.

**Status:** forms open, read, save and are signed, and queries are raised, answered, reopened, closed and cancelled, end to end on PostgreSQL through the kernel host. Edit checks (#5368), SDV (#5465) and locks (#5466) over the HTTP surface come next.

## Project

- Project: `apps/execution/module/Cadence.Modules.Execution.csproj`. Of the kernel it references only `Cadence.Kernel.Abstractions` and the module SDK `Cadence.Kernel.Modules` (K-XS-2), plus `Cadence.Core.Domain` and `Cadence.Security`; the kernel host references it.
- `ExecutionModule.AddCadenceExecutionModule(connectionString)` registers the module with the kernel's authorization (`AddCadenceModule`), its command store in the `execution` schema, the `OpenFormInstance` and query command handlers and validators, and the two event consumers. `MapExecutionModule()` maps the routes, each for a signed-in caller whose access the kernel then decides per object.
- `Domain/FormInstance`: one per kernel form instance, with the same id. It snapshots the CollectionSpec's item order from the governing protocol version when the form opens, so the screen keeps its layout.
- `Application/OpenFormOnCollectionOpened`: consumes the kernel's `CollectionInstanceOpened` event after commit and sends `OpenFormInstance` (`execution.form.open`) as `svc:execution-forms`, keyed by the delivery, so a redelivered event changes nothing twice. A kernel form the module cannot find, or that names another enrollment, is `M.Execution.Form.CollectionInstanceUnknown`.
- `Domain/FormQuery`: a data query about one revision of one value, targeting the kernel `(ObservationId, Revision)` (spec §11: the query workflow is EDC's). Status `open`, `answered`, `closed` or `cancelled`, with its conversation as `messages`. Raising refuses anything but the value's current revision (`M.Execution.Query.RevisionStale`) and a value of another form (`M.Execution.Query.ObservationUnknown`); a step its status does not allow is `M.Execution.Query.InvalidTransition`. Every query command shares the form's lock scopes first (ADR-2621) and is refused with 423 `K.Assertion.Locked` while a Locked lock covers the value; a Frozen lock stops data entry, not queries.
- `Application/MirrorFormQueryToKernel`: each query step raises `execution.FormQueryChanged` with the kernel assertion commands it stands for, and this consumer sends them as `svc:execution-queries`, keyed by the delivery: raising states a kernel `Queried` assertion about the observation, answering a `QueryAnswered`, closing or cancelling retracts the kernel query, reopening an answered query retracts the answer, and reopening a closed one raises a new kernel query (spec §8.2). The query chooses the assertion ids, so a redelivered event writes nothing twice; other applications count open queries from the kernel. A step refused because a Locked lock now covers the value is retried until the lock is released (#5586).
- `Endpoints/FormSignatureEndpoints`: the signing route. It verifies and spends the caller's step-up token, then sends the kernel's `SignCollectionInstance`, which records an `Attestation` over the form's content hash (ADR-2622 §4.5, #5463).
- `Infrastructure/ExecutionSignatureTokenDbContext`: the durable single-use store for spent step-up tokens (`AddCadenceDurableSigTokenStore`), table `execution.consumed_signature_tokens`, shared by every host instance so a token is spent once across them. It has no tenant column and no Row-Level Security: a token id is a random `jti`, and the store keeps nothing clinical.
- `Infrastructure/ExecutionModuleDbContext`: tables `execution.form_instances` and `execution.form_queries` with Row-Level Security on `tenant_id` (`ModuleTenantIsolationSql`), and the signature token table. `AddModuleMigrations` registers its migrations, which the host's `KernelMigrationHostedService` applies after the kernel's, and `ExecutionModuleDatabase.GrantAppRoleSql(role)` grants read, insert and update to the application role, and delete on the signature token table only, so expired tokens can be pruned. Reads outside commands use `AddModuleTenantContext` (a no-tracking context scoped to the caller's tenant).

## HTTP surface

Every route needs the gateway-signed caller, runs in the caller's kernel tenant (`KernelTenantFilter`) and answers RFC 9457 problem details with the kernel's stable error codes. Writes are kernel commands: they need an `Idempotency-Key` header, take the reason for change only from the signed identity, and are authorized against the form's enrollment. The wire is snake_case and values are typed (ADR-2623).

| Route (`/api/v1/execution/forms…`)        | Does                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST` (no suffix)                        | Opens a form (`OpenCollectionInstance`, `collection.open`) for an enrollment, CollectionSpec, optional visit and collection time, under the protocol version in force. 201; 409 `K.Observation.ParticipantWithdrawn` once the participant is withdrawn.                                                                                                                                                                                                               |
| `GET /{formId}`                           | The form: items in layout order with their values and revisions, `complete` and `missing_required` (every required item needs a value; a reasoned missing value counts), locks, assertions, `content_hash` and signatures, each `superseded` once a correction changed the form, with the values it signed. 403 when the caller may not see its enrollment.                                                                                                           |
| `PUT /{formId}/values`                    | Saves a page (`RecordCollectedValues`, `collection.record`): each value names the revision it was edited from. 409 `K.Collection.RevisionStale` refuses the whole page; 422 `K.Collection.ValuesInvalid` names each bad item; 423 when locked; 409 `K.Observation.ParticipantWithdrawn` for a new value once the participant is withdrawn (corrections go on).                                                                                                        |
| `POST /{formId}/signatures`               | Signs the form (`SignCollectionInstance`, `collection.sign`) with `meaning` (`approved` or `responsibility`) and the `content_hash` the signer read. Needs `X-Sig-Token`: a fresh single-use gateway step-up token for action `/api/v1/execution/forms/{formId}/signatures` and semantic action `execution.form.sign`; 401 `REAUTHENTICATION_REQUIRED` otherwise. 409 `K.Trust.TargetContentChanged` when the form changed since it was read. 201 with the signature. |
| `GET /{formId}/queries`                   | The form's queries, oldest first, each with `current_revision` and `value_changed` (a correction moved the value past the queried revision, so the monitor can close it). 403 when the caller may not see the enrollment.                                                                                                                                                                                                                                             |
| `GET /queries?enrollment_id=`             | The queries on every form of an enrollment, for the participant record. 403 when the caller may not see the enrollment.                                                                                                                                                                                                                                                                                                                                               |
| `POST /{formId}/queries`                  | Raises a query (`RaiseFormQuery`, `execution.query.raise`) on `observation_id` at its current `revision`, with `text`. 201.                                                                                                                                                                                                                                                                                                                                           |
| `POST /{formId}/queries/{queryId}/answer` | Answers an open query (`AnswerFormQuery`, `execution.query.answer`) with `text`.                                                                                                                                                                                                                                                                                                                                                                                      |
| `POST /{formId}/queries/{queryId}/reopen` | Reopens an answered or closed query (`ReopenFormQuery`, `execution.query.manage`) with `text`.                                                                                                                                                                                                                                                                                                                                                                        |
| `POST /{formId}/queries/{queryId}/close`  | Closes an open or answered query (`CloseFormQuery`, `execution.query.manage`); the reason for change is the closing note.                                                                                                                                                                                                                                                                                                                                             |
| `POST /{formId}/queries/{queryId}/cancel` | Cancels an open or answered query raised in error (`CancelFormQuery`, `execution.query.manage`).                                                                                                                                                                                                                                                                                                                                                                      |

There are no batch routes: a client acting on several queries sends one command per query.

The gateway forwards `/api/v1/execution/forms/**` to the kernel host (`KERNEL_SERVICE_URL`); the two-segment prefix wins over Execution's `/api/v1/execution/**` by routing precedence.

## Authorization

The coordinator needs `collection.open`, `collection.record` and `execution.query.answer` at the participant's study site; the investigator needs `collection.sign` there (the demo user `pi.site101` has it); the monitor or data manager needs `execution.query.raise` and `execution.query.manage`. Without a grant every query command is denied (403 `K.Authorization.Denied`).

The consumers' service accounts need tenant-wide grants in every tenant that uses forms: `svc:execution-forms` needs `execution.form.open`, and `svc:execution-queries` needs `observation.query`, `observation.query.answer` and `assertion.retract`. In Development the kernel host's demo data issues them (`DEMO_EXECUTION_FORMS`, `DEMO_EXECUTION_QUERIES`); provisioning them in production is #5566.

## Tests

- `tests/Cadence.IntegrationTests/Execution/ExecutionFormModulePostgresTests.cs` (PostgreSQL, application role): opening a kernel form opens the module's form with the specification's item order, as `svc:execution-forms` with the delivery's idempotency key; a redelivered event opens one form; unknown, mismatched and existing forms are refused.
- `tests/Cadence.IntegrationTests/Execution/ExecutionFormHostPostgresTests.cs`: the real kernel host with a signed coordinator opens a form, saves pages, derives completeness and refuses a stale page whole; a caller without a grant can neither read nor save.
- `tests/Cadence.IntegrationTests/Execution/ExecutionFormQueryPostgresTests.cs` (PostgreSQL, application role): a query on a revision is stated as a kernel `Queried` assertion, answered and retracted on close, once however often the event is delivered; reopening withdraws the answer or raises a new kernel query; a cancelled query is final; a Locked lock refuses raising and answering, a Frozen one does not.
- `tests/Cadence.IntegrationTests/Execution/ExecutionFormQueryHostPostgresTests.cs`: through the kernel host, a monitor raises, the coordinator answers and corrects the value, the query shows the value changed and is closed; the coordinator can neither raise nor close and a stranger sees nothing (403).
- `tests/Cadence.IntegrationTests/Execution/ExecutionFormSignatureHostPostgresTests.cs`: through the kernel host, an investigator signs revision 1, a correction marks that signature superseded with the value it signed, a stale hash is refused (409) and a second signature is current; each signature writes an audit entry. A missing, expired, replayed or foreign step-up token is refused (401), a coordinator without `collection.sign` is denied (403) and an unknown meaning is refused (422).
- `tests/Cadence.UnitTests/Kernel/CollectionContentHashTests.cs`: the form content hash ignores read order and changes with every revision and value.
- `tests/Cadence.UnitTests/Execution/Module/ExecutionFormQueryTests.cs`: the steps each status allows and the kernel assertion each states.
