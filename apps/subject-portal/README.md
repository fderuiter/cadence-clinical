# Subject portal

Participant-facing eCOA/ePRO and eConsent web app (Vue 3, Vite) with an offline sync queue and a service worker. In the Vite dev server it calls its own origin, and the dev server's `/api` proxy forwards to the API gateway (`CADENCE_GATEWAY_URL`, default `http://localhost:8000`), because the gateway sends no CORS headers (#5451). The AppHost's `full` profile runs it on port 5174.

### State, router and views

- **State.** The Pinia stores hold the portal's state. The feature modules (and the tests) use `state` from `src/stores/state.js`: one object whose top-level keys (`state.session`, `state.assignments`, `state.currentView`, ...) read and write the store that declares them, so it behaves like the single reactive object the portal used to keep. Components use the stores directly.
- **Views stay mounted.** The feature modules render tasks, compliance, the inbox, consent and the sync queue into elements by id (`tasks-list-container`, `compliance-history-tbody`, ...), so all views are always in the DOM; `state.currentView` decides which one has the `active` class, toggles `hidden` and `inert` on inactive `.portal-view` sections, and selects the active tab.
- **Router & availability guards.** `vue-router` uses `createWebHistory(ROUTER_BASE)` in standard and production builds and `createWebHashHistory(ROUTER_BASE)` in static `demo` builds (`ROUTER_BASE` defaults to `/subject-portal/` and honours `VITE_BASE_PATH`, such as `/cadence-clinical/subject-portal/` on GitHub Pages, [ADR-2550](../../docs/adr/2026-11-20-co-host-interactive-demos-on-github-pages-subpaths.md)), giving each view a URL: `/` (tasks), `/questionnaire`, `/compliance`, `/inbox`, `/consent`, `/wallet`, `/lay-summaries`, and `/unavailable`. Outside explicit `demo` builds, unbacked participant sections (`tasks`, `questionnaire`, `compliance`, `inbox`, `consent`, and `lay-summaries`) are excluded from `AVAILABLE_SCREENS` while `wallet` remains enabled for authenticated participants (`AUTHENTICATED_SCREENS`), so signed-in participants opening `/` land on `/wallet`, direct visits to unbacked sections render `/unavailable` (`UnavailableView.vue`) with a return action to Participant Wallet (or Sign In when signed out) without looping back to `/tasks`, and boot skips unmounted `/api/v1/interop/*` and `/api/v1/econsent/*` endpoints. In `demo` builds, a deep link to `/questionnaire` without a questionnaire in progress opens My Tasks.
- **PIN-wrapped offline encryption & recovery (ADR-2360).** Queued ePRO submissions and drafts are AES-GCM encrypted in per-user IndexedDB (`SubjectPortalSyncDB_${userId}`). Only the PBKDF2-wrapped master key is stored in `config`; the unwrapped key lives strictly in JavaScript memory after PIN setup or PIN unlock and is cleared on page reload, user switch, or sign-out. `PinUnlockModal` caps consecutive failed PIN attempts at five, pauses unlock attempts when reached, and provides keyboard-accessible Sign Out, identity-verified (OIDC) PIN reset (generating a fresh local master key while flagging prior undecryptable entries without exposing clinical PII), and site support links.
- **Offline sync isolation, retry countdowns, drafts & site support.** Manual sync controls in `SyncSuspendedBanner` and `SyncDrawer` reload active survey definitions and clear resolved version-mismatch suspensions. When a multi-item `/api/v1/interop/epro/sync` batch encounters validation errors, valid surveys submit individually via `/api/v1/interop/epro/submit` while invalid surveys are marked `LOCAL_QUARANTINED` with plain-language guidance and coordinator next steps. Transient network errors schedule automatic exponential retries with a live second-by-second countdown. Required visual analog scale (VAS) sliders stay `"Not answered"` until touched so untouched surveys cannot submit a default zero. Navigating back or switching tabs/routes from an active survey immediately flushes partial encrypted answers (`Resume Survey`), canceling prompts confirmation before discarding, and offline-cached coordinator `tel:` and `mailto:` links (`SiteContactLinks`) appear in `ParticipantCard`, `SyncDrawer`, `PinUnlockModal`, and `InboxView`.

## Backend and authentication

- Requests go to `<base>/api/v1/...`; paths without an `api/v1/` prefix are sent to `/api/v1/interop/...`. The base is `VITE_API_BASE_URL`, read in `src/api/client.js`: the dev server's own origin (`http://localhost:5174`) in `vite` dev unless set, `globalThis.location.origin` in `demo` builds (`--mode demo` or `VITE_DEMO_MODE=true`) when unset so static hosts never call `http://localhost:8000`, and `http://localhost:8000` in standard builds and tests. Do not point it at the gateway from the dev server: the browser blocks the cross-origin call.
- When Keycloak sign-in succeeds (`VITE_KEYCLOAK_URL`, `VITE_KEYCLOAK_REALM`, `VITE_KEYCLOAK_CLIENT_ID`; defaults `http://localhost:8080/`, `cadence`, `cadence-web`), the access token is sent as `Authorization: Bearer <token>`. `src/features/auth.js` and `src/api/client.js` share `createOidcSessionCoordinator` (`ui`) so `onTokenExpired`, `onAuthRefreshSuccess`, and HTTP `401` responses run one single-flight refresh before transitioning `ParticipantCard.vue` to `Session Expired` with a direct `Sign In Again` action while keeping encrypted IndexedDB questionnaire drafts intact and restoring the return URL after sign-in ([ADR-2551](../../docs/adr/2026-11-20-share-session-logout-and-signature-primitives.md)). Voluntary sign-out flushes debounced questionnaire drafts and prompts `SignOutConfirmModal` (`useSignOutGuard` from `ui`) before clearing `activeQuestionnaire` when unsaved progress exists. The dev realm's `cadence-web` client allows the portal's redirect URIs (`http://localhost:5174/subject-portal/*` and `http://localhost:5174/*`) and seeds a deterministic participant account (`subject.site101`, role `Subject`, scoped to `tenant_id: cadence-local`, `study_ids: CADENCE-101`, `site_id: SITE-101` with zero staff kernel grants per K027) in `docker/cadence-realm.json`. Without a token in production mode, the portal prompts the user to sign in and never populates synthetic study data.
- In explicit `demo` builds (`pnpm --filter subject-portal dev:demo` or `build:demo`), `initializeApp` (`src/bootstrap/initialize.js`) awaits `startMswWorker()` (`src/mocks/browser.js`) before mounting views or loading assignments, registering `${BASE_URL}sw.js?msw=1` under scope `${BASE_URL}` (for example `/subject-portal/` locally or `/cadence-clinical/subject-portal/` on GitHub Pages) while skipping standalone PWA registration so offline shell caching (`public/sw.js`) and MSW API interception (`public/mockServiceWorker.js`) share one worker registration per subpath without evicting each other or deleting `msw:` client caches. `login()` (`src/features/auth.js`) activates the synthetic demo participant (`subject_001`) locally without contacting Keycloak (`http://localhost:8080/`), zero-argument `isDemoBuild()` calls are constant-folded at Rollup build time (`createConstantFoldDemoModePlugin`) so `keycloak-js` is omitted from demo bundles ([ADR-2537](../../docs/adr/2026-11-22-split-ui-vitest-matcher-and-enforce-demo-bundle-budgets.md)), and `buildPortalGatewayHandlers()` (`src/mocks/handlers.js`, `src/mocks/demoHandlers.js`) fails closed on unmocked API routes (`501 DEMO_UNMOCKED_ENDPOINT`) and off-origin requests (`503 DEMO_OFF_ORIGIN_BLOCKED`) while keeping in-memory session state across ePRO submissions, notification acknowledgements, and re-consent signatures. Production builds (`pnpm --filter subject-portal build`) tree-shake demo handlers and strip `mockServiceWorker.js` from `dist/`.
- Electronic consent and protocol amendment re-consent require live step-up verification (`/api/v1/auth/signature-verification` via shared `buildStepUpVerificationPayload`, `SIGNATURE_PASSWORD_INPUT_ATTRS`, and `"Other"` custom reason validation from `ui`) and backend persistence outside `demo` builds; offline symptom diaries remain in `PENDING_SYNC` (`Pending Sync`) until `/api/v1/interop/epro/sync` confirms persistence.

## Scripts

Run from the repository root with pnpm:

| Command                                   | Purpose                                                                                                                    |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `pnpm --filter subject-portal dev`        | Vite dev server on `http://localhost:5174/subject-portal/`.                                                                |
| `pnpm --filter subject-portal dev:demo`   | Vite dev server in explicit `demo` mode with synthetic study data.                                                         |
| `pnpm --filter subject-portal build`      | Production build. Build `ui` first (`pnpm --filter ui build`).                                                             |
| `pnpm --filter subject-portal build:demo` | Demo build (`--mode demo`) with explicit synthetic data banner.                                                            |
| `pnpm --filter subject-portal test`       | Vitest with coverage (80% thresholds on `src/sync-queue.js`).                                                              |
| `pnpm --filter subject-portal test:e2e`   | Playwright (accessibility, PIN recovery, and `/cadence-clinical/subject-portal/` staged subpath worker + chunking checks). |
| `pnpm --filter subject-portal lint`       | ESLint.                                                                                                                    |

`docker/docker-compose.yml` also runs the dev server as the `subject-portal` service on port 5174.

## Dependencies

- Runtime: `vue`, `vue-router`, `pinia` and the workspace packages [ui](../../packages/ui/README.md) and [usdm-schemas](../../packages/usdm-schemas/README.md); `keycloak-js` is loaded on demand.
- Development: Vite, Vitest, Playwright with `@axe-core/playwright`, MSW, `fake-indexeddb`, `jsdom`.
