# ui

Shared frontend package (JavaScript, TypeScript types and Vue 3 components) used by the web client and the subject portal.

## Contents

- `index.js` (main entry, resolved directly from workspace source by consuming apps and built to `dist/` as an ES and CJS library): helpers such as `debounce`, `createSrOnlyActionButton` (accessible DOM button builder appending `.sr-only` context while preserving leading visible verbs per WCAG 2.2 SC 2.5.3), HTML builders for lookup inputs, rule editors and schedule-of-activities matrices, condition-tree serialisation, `initHoverDetection`, and re-exports of the modules and components below.
- `signing.js`: browser-side hashing, canonical serialisation, AES-GCM helpers (`sha256`, `canonicalSerialize`, `encryptAESGCM`, `deriveKeyFromPIN`), and 21 CFR Part 11 v3 step-up helpers (`SEMANTIC_ACTIONS`, `isValidSemanticAction`, `buildStepUpVerificationPayload`, `SIGNATURE_PASSWORD_INPUT_ATTRS`, `requiresCustomSignatureReason`, `resolveSignatureReason`, `deriveSignerRoleFromClaims`).
- `session.js`: shared OIDC session coordinator (`createOidcSessionCoordinator`) providing `onTokenExpired` / `onAuthRefreshSuccess` registration, single-flight `updateToken` deduplication, one-shot `401` refresh-and-retry, draft-preserving involuntary expiry transitions, and safe same-origin return-URL persistence (ADR-2551).
- `callerScope.js`: framework-neutral OIDC claim and scope helpers (`parseClaimStringList`, `decodeJwtPayloadClaims`, `extractAssignedStudies`, `extractAssignedSites`, `extractPrimaryStudyId`, `extractPrimarySiteId`, `isForbiddenScopeError`, `formatScopeForbiddenGuidance`) shared by `apps/web` and `apps/subject-portal` so `studyId` and `siteId` derive deterministically from token claims (`study_id`, `study_ids`, `site_id`, `site_ids`) without hardcoded fallback identifiers ([ADR-2657](../../docs/adr/2026-11-23-share-ui-primitives-and-query-synced-portal-routes.md)).
- `mockGateway.js`, exported only as `ui/testing`: the gateway simulator and MSW service-worker coordination helpers for static demo builds and tests (`validateGatewayRequest`, `isGatewayApiCall`, `isPathSignatureGated`, `normalizeMswBasePath`, `resolveMswServiceWorkerOptions`, `waitForMswController`, `ensureServiceWorkerController`, `createMswWorkerStarter`, `evaluateDemoBoundaryRequest`). It imports neither `msw` nor `msw/browser`, is not part of the root export, and holds no secret: it verifies an `X-Gateway-Signature` only against a secret the caller passes as `options.secret`, and rejects one it cannot check. Real authentication happens in [apps/gateway](../../apps/gateway/README.md).
- `econsent.js`: consent normalisation and comprehension-check helpers.
- `accessibility-matcher.js`, exported only as `ui/vitest` (typed via `accessibility-matcher.d.ts`): `toBeAccessible` Vitest matcher built on `axe-core` ([ADR-2537](../../docs/adr/2026-11-22-split-ui-vitest-matcher-and-enforce-demo-bundle-budgets.md)). It is excluded from the root `ui` runtime bundle so `axe-core` never ships in production or demo builds.
- `src/components/`: 29 shared Vue components re-exported from the root `ui` entry (`FileUploadModal`, `MediaPlayer`, `ModalErrorAlert`, `common/EmptyState`, and `clinical/` components `AiActionButton`, `AiSuggestionDrawer`, `AuditLogViewer`, `ClinicalBreadcrumbs`, `ClinicalContextBar`, `ClinicalDataTable`, `ClinicalDrawer` [side drawer plus `position="bottom"` / `mobileBottomSheet` `90dvh` safe-area bottom sheet], `ClinicalDropzone`, `ClinicalFieldLayout`, `ClinicalFormField` [auto-propagating `data-tabular-nums="true"` for numeric/date CDASH fields], `ClinicalIcon`, `ClinicalIconButton`, `ClinicalInput` [`type`, `inputmode`, and `tabularNums` / `data-tabular-nums` alignment], `ClinicalLookupInput`, `ClinicalModal`, `ClinicalQueryFlag`, `ClinicalQueryPanel`, `ClinicalRadioGroup`, `ClinicalTabs` [`underline`, `pills`, and `segmented` variants, `scroll`/`wrap` overflow modes with edge fade cues, `44px` hit targets, and reduced-motion-aware focus scroll alignment per [ADR-2659](../../docs/adr/2026-11-23-centralize-clinical-tabs-variants-overflow-and-scoped-css-gates.md)], `ClinicalToastHost`, `ConfidenceBadge`, `EntityLink`, `EntityPeekDrawer`, `PersonaSwitcher`, `SignOutConfirmModal`) plus DIA TMF & entity resolution helpers (`DIA_TMF_ARTIFACT_CATALOG`, `resolveDiaArtifactMeta`, `resolveEntityLinkDescriptor`, `buildEntityBinderUrl`, `humanizeEntityStatus`, `normalizeEntitySubjectCode`, [ADR-2672](../../docs/adr/2026-11-23-shared-entity-link-drawers-and-scoped-etmf-sync.md)).
- `src/composables/`: reactive `useFocusTrap(targetRef, options)` (focus containment, LIFO nested overlay stack, background sibling `inert`/`aria-hidden="true"` reconciliation with `[data-focus-trap-exempt="true"]` live-alert exemptions and `Tab` bridging, `Escape` dismissal or lock-screen blocking, and trigger focus restoration with `options.fallbackFocus`, parent-trap stack fallback, and visible fallback focus restoration when triggers unmount or hide), `hasActiveModalFocusTrap(options)`, `getTopActiveModalContainer()`, `handoffFocus(targets, options)` and `useInlineFocusHandoff(options)` (non-trapping inline focus handoff, visibility/inert verification after `nextTick`, `tabindex="-1"` programmatic heading handoff, and trigger restoration across `v-if` swaps and portal view transitions), `useEscapeClose(onClose, options)` (LIFO topmost dismissal for non-trapped overlays), `getFocusableElements(container)`, `trapTabFocus(event, container)`, `useAsyncRetry`, and `useSignOutGuard` (flushes debounced drafts and requires explicit confirmation before destructive sign-out cleanup when unsaved work exists), all re-exported from the root `ui` entry. `src/types/cdash.ts`: CDASH types.

## Scripts

| Command                      | Purpose                                                             |
| ---------------------------- | ------------------------------------------------------------------- |
| `pnpm --filter ui build`     | Generates types, then builds the library with Vite.                 |
| `pnpm --filter ui test`      | Vitest (`tests/`) with coverage.                                    |
| `pnpm --filter ui lint`      | ESLint.                                                             |
| `pnpm --filter ui typecheck` | Strict `vue-tsc --noEmit` across `index.d.ts`, Vue SFCs, and tests. |

## Coverage

`pnpm --filter ui test` measures coverage over every source file, components included (ADR-2530). The global thresholds
in `vite.config.js` are a ratchet floor: raise them when coverage rises, never lower them. `signing.js` and
`econsent.js`, the Part 11 signing and eConsent helpers, carry an 80 percent gate of their own.

## Dependencies

- Runtime: peer dependency `vue` (no runtime npm packages bundled into `dist/`).
- Development: Vite, Vitest with `@vitest/coverage-v8`, `axe-core` (backing `ui/vitest`), TypeScript, `vue-tsc`, `pinia`.

## Used by

[apps/web](../../apps/web/README.md) and [apps/subject-portal](../../apps/subject-portal/README.md) (`"ui": "workspace:*"`). Both apps resolve `ui`, `ui/testing`, `ui/vitest`, `ui/tokens.css`, and `ui/responsive.css` directly from workspace source during local development, Vitest runs, and application builds ([ADR-2658](../../docs/adr/2026-11-23-resolve-shared-ui-from-source-and-align-verification-scripts.md)); `pnpm --filter ui build` remains available to regenerate `index.d.ts` and validate the library bundle.
