# Cadence.ToolingCore

Implementation library behind the Cadence CLI: repository validators, generators and gate runners, plus three standalone tools (OpenAPI specs, database schema docs, and the design-time PostgreSQL database migrator).

## Projects

- `packages/tooling_core/src/Cadence.ToolingCore.csproj` (assembly `Cadence.ToolingCore`):
  - `Cadence.ToolingCore.Services`: one static service per tool, plus `BaselineUnitPath` (shared `apps/<name>`, `packages/<name>`, and `root` baseline shard path resolver and empty-directory pruner), `PosixProcessLauncher` (cross-platform `UseShellExecute = false` process launcher resolving Windows `.exe`/`.cmd`/`.bat` shims in `PATH` directory order with custom `PATH` overrides and POSIX `/bin/sh` `ENOEXEC` fallback), `GitRevisionScopeService` (centralized staged, branch `--base`, push `--push-before`, and `git ls-files -z` tracked-file diff scoping), `GitIndexReader` and `StagedBlobWorkspace` (lock-free staged Git index blob reader via `git cat-file --batch` and disposable workspace materializer for `--pre-commit` gates), `ExporterBinaryResolver` (timestamp-verified direct reuse of prebuilt `bin/Debug/net10.0` or `bin/Release/net10.0` exporter assemblies with automatic `dotnet run --project` rebuild on stale C# or MSBuild inputs) and `ExporterBuildFreshness` (`--no-build` freshness check across transitive `<ProjectReference>` inputs for `Cadence.OpenApiExporter` and `Cadence.SchemaDocExporter`), `DoctorProvisioningService` (AOT-safe cross-platform `cadence doctor --auto-fix` provisioning for SHA-256-verified `.cadence/bin` linters, `.cadence/venv` `detect-secrets`, `dotnet tool restore`, `pnpm` workspace dependencies, `.env`, and `.githooks/pre-commit`), `CliLinterGateService` (fail-closed `actionlint`, `hadolint`, and `shellcheck` gates from `.cadence/bin` or `PATH`), `WorkflowSecurityValidatorService` (GitHub Actions workflow security, 40-char commit SHA pinning, `sha256:` container digests, `persist-credentials: false`, fork-checkout and PR-write fork-guard enforcement, typed/ref-guarded `workflow_dispatch` controls, masked shell error detection, and least-privilege permissions), `YamlSyntaxValidatorService` (Native AOT YAML 1.2 validator), `FileHygieneValidatorService` (`trailing-whitespace` and `end-of-file` newline checks), `FrontendQualityGateService` (fail-closed Prettier check/format, ESLint streaming staged blobs over `stdin`, and workspace `pnpm -r typecheck` gates under `--pre-commit`), `DetectSecretsGateService` (fail-closed bounded-parallel `detect-secrets-hook` gate materializing per-batch temporary baselines from `baselines/secrets/config.json` and `*.secrets.baseline.json` shards, resolving `.cadence/venv`, `.venv`, `PATH` or `uvx`), `SecretsBaselineCleanerService` (canonical `baselines/secrets/` shard splitter/cleaner, non-mutating `--check` verifier, and file-exclusion regex), `DuplicationDetectorService` (multi-language `.cs`, `.js`, `.ts`, `.tsx`, `.vue`, and `.css` clone detector ratcheted by shrink-only `.duplication-baseline.txt`), `ReadmeValidatorService`, `MarkdownValidatorService`, `AdrValidatorService`, `ArchitectureDriftValidatorService`, `ImportValidatorService` (cross-service direct import, qualified namespace, and reflection string-literal scanner across `apps/<service>`, ratcheted by `cross-service-isolation.baseline.txt`), `DependencyValidatorService` (fail-closed JSON/XML, MSBuild cohort, `xunit.v3`/`TngTech.ArchUnitNET.xUnitV3`, `pnpm-workspace.yaml` `catalog:`, `.github/dependabot.yml`/`.yaml` target/ignore uniqueness via `ValidateDependabotContent` and group/ignore rules, `PostgresTestImage.cs` `@sha256` digest parity, client-side crypto, and runtime test-harness checks across working-tree and staged `--pre-commit` blobs), `VulnerabilityAuditorService` (fail-closed `.NET` and `pnpm` CVE auditing against `docs/SDLC/vulnerability_exclusions_ledger.json`, scoped to modified ecosystem manifests/lockfiles/ledger in `--pre-commit`), `ApiClientValidatorService` (verifies generated OpenAPI client types and runs `pnpm -r typecheck`, scoped to `docs/openapi/` and frontend/canvas-contract inputs in `--pre-commit`), `DemoManifestGeneratorService` (exports and verifies `packages/demo-fixtures` from `packages/demo-fixtures/demo-seed.json`, `ExecutionDbSeeder.cs`, and `docker/cadence-realm.json` via source-generated `System.Text.Json`), `SyncGxPService`, `ScaffoldServiceService`, `SelfHealService` (subdirectory-safe `cadence fix` pipeline with diff-based schema, OpenAPI, and web client type regeneration, plus canonical demo manifest sync), `OpenApiSyncService`, `PreCommitOpenApiService` (reverse `<ProjectReference>` graph traversal mapping staged or targeted backend edits to dependent OpenAPI-exporting hosts), `PersistenceModuleCatalog` and `MigrationToolingService` (canonical 18-module persistence catalog and `cadence migrations add|script|list|verify` workflow writing SQL scripts to `TestResults/migrations/`), `SchemaDocGeneratorService`, `PublicBundleValidatorService` (the zero-exemption `public-bundle` gate over compiled static portal and demo bundles, enforcing `axe-core`/`keycloak-js` absence, preload hygiene, and staged demo byte budgets), and `DeidComplianceService` (the `deid` gate: the full `DeidDetector` over changed or tracked candidate files, ratcheted by `baselines/deid/<unit>.baseline.txt` shards with matched-token digests).
  - `Cadence.ToolingCore.Markdown`: `MarkdownParser` (workspace link and `#anchor` heading fragment checking, and paths into .NET test project folders that no longer exist; `docs/migration/` and the generated RTM and IQ/OQ/PQ report are skipped for test-path checks).
  - `Cadence.ToolingCore.Security`: `SecretScanner`.
  - `Cadence.ToolingCore.OpenApi`: `OpenApiToolingService`, and `OpenApiSpecExporter` (currently writes placeholder documents with empty `paths`).
  - `Cadence.ToolingCore`: `ToolingHandlers` and request/response records (`Contracts.cs`) intended for MCP tools; only the unit tests call them today.
- `packages/tooling_core/src/Cadence.OpenApiExporter/Cadence.OpenApiExporter.csproj`: console app that loads all 17 ASP.NET Core hosts concurrently in-process (up to 4 workers by default, configurable via `--max-parallelism`) with buffered per-service logging and ordinal aggregation, writing OpenAPI documents (default `docs/openapi`, override with `--output-dir` / `-o`).
- `packages/tooling_core/src/Cadence.SchemaDocExporter/Cadence.SchemaDocExporter.csproj`: console app that creates each of the 18 persistence modules' DbContexts (`PersistenceModuleCatalog.All`: `kernel`, `intelligence`, `executionmodule`, and 15 standalone apps) through its design-time factory, verifies `HasPendingModelChanges()`, `[DbContext]`, `[Migration]`, `.Designer.cs` companions, and `CreateTable`/`AddColumn` uniqueness (`SchemaMigrationValidator`), renders count-free Markdown with `SchemaDocumentation` from [packages/database](../database/README.md), and writes `docs/schema/<module>.md` plus `README.md` (default `docs/schema`, override with `--output-dir` / `-o`, or `--verify-only [--module <name>]`). It never opens a database connection. `SchemaDocGeneratorService` and `MigrationToolingService` run it for `generate-schema-doc`, `check schema-doc`, and `migrations verify`.
- `packages/tooling_core/src/Cadence.DatabaseMigrator/Cadence.DatabaseMigrator.csproj`: non-AOT console app that loads all 18 design-time `DbContext` assemblies (`PersistenceModuleCatalog.All`), pre-creates the 15 `SearchPath` service schemas, and applies pending EF Core PostgreSQL migrations across all 19 schemas (`kernel`, `identity_vault`, `execution`, `intelligence`, and 15 service schemas) out of process so `Cadence.Cli` stays `PublishAot=true`.
- Time (K-TIME-3): all four projects ban `DateTime.Now/UtcNow`. `CreateAdrService.CreateAdr` takes the date.
